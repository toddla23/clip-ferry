# F10. 데스크톱 페어링 UI — 확인할 것

상태: `확인대기` (docs/05-progress.md)

## 먼저 알아둘 것

- **첫 실행 동작이 바뀌었다.** F09의 "처음 실행하면 그룹 자동 생성"은 없어졌다. 이제 마법사가 뜬다: 기기 이름(컴퓨터 이름이 미리 채워짐) → `새 그룹 만들기` 또는 `코드로 참여`. **F09 때 이미 그룹을 만든 상태라면 마법사 없이 바로 메인 화면**이 뜨므로, 마법사를 보려면 아래 "개발용 프로필"을 쓴다.
- **페어링 진행 로직을 코어로 옮겼다**(`core/src/pair_flow.rs`). CLI의 `invite`/`join`에 있던 릴레이 진행(구독·재전송·승인·거절)을 셸이 다시 짜지 않도록 코어에 같은 흐름을 만들었고, 데스크톱이 이것을 쓴다. **CLI는 건드리지 않았다**(F06에서 승인된 동작 유지). 그래서 지금은 같은 흐름이 CLI와 코어에 두 벌이다 — CLI를 `pair_flow`로 갈아끼우는 정리는 필요하면 따로 하자.
- **개발용 프로필**: 환경 변수 `CF_DESKTOP_PROFILE=<이름>`을 주면 그 앱은 `%APPDATA%\app.clipferry.desktop\profiles\<이름>` 폴더와 Credential Manager의 `…clip-ferry-<이름>` 항목을 따로 쓴다. 한 PC에서 앱 두 개를 띄워 페어링을 시험하거나, 기존 프로필을 건드리지 않고 첫 실행을 보려고 쓴다. 영문·숫자·`-`·`_`만 허용.
- 승인 뒤 상대 기기가 환영 메시지를 받지 못한 것 같으면(`delivered=0`) 완료 화면에 경고를 띄운다. 이때 로스터에는 이미 들어가 있으므로 기기 제거(F13 UI, 지금은 `cf remove`)로 정리한다.
- 아직 없는 것: 기기 제거·이름 변경 UI(F13), "다시 페어링 필요" 전용 화면(F13), 온라인 표시(F13).
- 창 높이를 430 → 580으로 키웠다(초대 화면의 QR·코드·버튼이 들어가야 한다).

## 직접 확인할 것 (PowerShell)

사전 준비: 릴레이 `cargo run -p clip-ferry-relay -- --listen 127.0.0.1:8787` 한 개. 아래 앱 두 개는 **서로 다른 프로필**이어야 한다. 먼저 UI를 한 번 빌드(`cd apps\desktop; npm install; npm run build`).

터미널 A (앱 1): `$env:CF_DESKTOP_PROFILE="pc1"; cd apps\desktop; npm run tauri dev`
터미널 B (앱 2, 앱 1이 뜬 뒤): 두 번째 `tauri dev`는 UI 서버 포트(1420)가 겹쳐 실패하므로, 앱 1이 띄운 UI 서버를 같이 쓰도록 실행 파일을 직접 연다:
`$env:CF_DESKTOP_PROFILE="pc2"; $env:WEBVIEW2_USER_DATA_FOLDER="$env:TEMP\wv-pc2"; .\target\debug\clip-ferry-desktop.exe`
(앱 1과 WebView2 데이터 폴더를 따로 두기 위해 `WEBVIEW2_USER_DATA_FOLDER`를 준다.)

1. [ ] 앱 1: 마법사가 뜬다. 이름 칸에 컴퓨터 이름이 들어 있고, 이름을 바꿔 `새 그룹 만들기` → 메인 화면에 `연결됨`, 기기 1대(`이 기기` 표시)
2. [ ] 앱 1: `기기 추가` → QR, 텍스트 코드, `남은 시간 10:00`부터 줄어드는 것이 보인다. `코드 복사` → `복사했습니다`
3. [ ] 앱 2: 마법사 → 이름 → `코드로 참여` → 코드 붙여넣기 → `참여`. 앱 2에 `…기기 화면에 아래와 같은 숫자가…`와 6자리 숫자
4. [ ] 앱 1에 `참여 요청` 화면과 **같은 6자리 숫자**가 뜬다. `같음, 승인` → 앱 1 `기기를 추가했습니다` → `확인` → 기기 2대. 앱 2는 자동으로 메인 화면(`연결됨`, 기기 2대)
5. [ ] 반대 방향: `cargo run -q -p clip-ferry-cli -- --profile y init --name cli-y` → `group create` → `invite`. 새 앱 프로필(`pc3`)의 마법사에서 `코드로 참여`로 그 코드를 넣으면 숫자가 같고, CLI에서 `y` 입력 시 앱이 메인 화면으로 간다
6. [ ] 거절: 앱 1 `기기 추가` → 다른 프로필이 참여 → `거절` → 참여 쪽에 "거절했거나 만료" 문구, 앱 1 기기 목록은 그대로
7. [ ] 잘못된 코드(한 글자 바꿔서) → 한국어 오류 문구, 마법사 화면 유지
8. [ ] 앱 1 초대 화면에서 `취소` → 메인 화면으로 돌아온다. 취소한 초대 코드로 다른 프로필이 참여를 시도하면 응답이 오지 않는다(참여 쪽은 `취소`로 나올 수 있다)

정리(선택): 앱 종료 후 `Remove-Item -Recurse $env:APPDATA\app.clipferry.desktop\profiles` 와 `cmdkey /list | Select-String clip-ferry-pc` 로 나온 항목을 `cmdkey /delete:<이름>` 으로 삭제.

## 참고

- 구조: 셸(`apps/desktop/src-tauri/src/shell.rs`)이 `pair_flow::start_invite/start_join`을 불러 진행 상태를 `PairingView`로 화면에 보낸다. 늦게 도착한 이전 진행의 알림은 진행 번호로 걸러낸다.
- 화면: `Wizard`(첫 실행) / `Home`(메인) / `Pairing`의 `InviteScreen`·`JoinScreen`. QR은 코어가 만든 초대 링크를 Rust에서 SVG 경로로 만들어 화면이 그대로 그린다.
- 초대 링크(QR)에는 현재 릴레이 주소가 들어간다. 릴레이 주소가 `127.0.0.1`이면 다른 PC·폰에서는 쓸 수 없다. 다른 기기와 하려면 먼저 릴레이 주소를 서로 닿는 주소로 바꿔 저장한다(F14에서 공개 릴레이 기본값이 생긴다).
- 참여 쪽 릴레이는 초대에 들어 있는 주소를 우선 쓰고, 없으면 설정의 릴레이 주소를 쓴다.

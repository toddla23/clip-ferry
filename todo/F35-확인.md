# F35. Android 로그인 — 확인할 것

상태: `확인대기` (docs/05-progress.md). 브랜치 `f35-android-login` (F34 완료 커밋 위).

이 문서만 보고 처음부터 끝까지 따라 할 수 있게 썼다. 각 단계는 **할 일 → 보여야 하는 것** 순서다. 다르게 보이면 맨 아래 "막히면"을 먼저 보고, 그래도 안 되면 그 화면·로그를 "시험 중 나온 것"에 적는다.

## 무엇을 시험하나

- Android 앱이 **구글 로그인을 한 뒤에만** 릴레이에 연결한다. 로그인 전에는 로그인 화면만 보이고, 상시 알림·타일·공유 메뉴도 연결하지 않는다.
- 로그인: 앱의 `Google로 로그인` → 폰의 구글 계정 선택 창(아래에서 올라오는 시트) → 앱으로 돌아온다. 브라우저는 열리지 않는다.
- 지금 쓰는 폰 앱(그룹·페어링이 있음)을 업데이트해도 **그룹은 그대로**이고 로그인만 하면 이어서 쓴다. F15~F19 기능(받기·타일·알림 버튼·공유)이 그대로 된다.
- 앱을 다시 켜도 로그인이 유지된다. 갱신 토큰은 폰의 보안 저장소(Keystore)에, 1시간짜리 접속 토큰은 메모리에만 둔다.
- 로그아웃하면 연결을 끊고 로그인 정보를 지운다. 그룹은 남는다.
- 구글 비밀값은 앱에 없다. 앱은 계정 서버에서 "웹 클라이언트 ID"를 받아 구글 창에 넘기고, 받은 ID 토큰을 계정 서버에 낸다(D-021).

## 시험 구성

```
Pi     계정 서버   https://raspberry-pi.tailb6b7a3.ts.net:8443   (이 브랜치로 다시 빌드, 실제 구글 로그인)
Pi     릴레이      wss://raspberry-pi.tailb6b7a3.ts.net           (지금 돌고 있는 그대로, 토큰 확인 안 함)
폰     clip-ferry  이 PC에서 USB로 설치(디버그 빌드)
PC     설치된 clip-ferry (예전 버전, 그대로 둔다)   — 폰과의 동기화 회귀 확인용
PC     (6절, 선택) 토큰을 확인하는 릴레이 ws://<PC Tailscale IP>:8787
```

- 폰의 Tailscale은 켜 둔다(F15~F19 때와 같다).
- Pi 릴레이는 아직 토큰을 확인하지 않는다. 그래서 1~5절 동안 PC(예전 버전)와 폰(로그인함)이 지금처럼 동기화된다. 토큰을 확인하는 릴레이는 6절에서 PC에 따로 띄워 본다.

## 0. 구글 콘솔: Android 클라이언트 만들기 (한 번만)

F32 때 만든 프로젝트(`clip-ferry`)를 그대로 쓴다. 구글은 "이 패키지 이름 + 이 서명 키"로 만든 앱이 프로젝트 소속일 때만 로그인 창을 띄워 준다. 그 등록이 Android 클라이언트다.

1. https://console.cloud.google.com/ → 위쪽 프로젝트가 `clip-ferry`인지 확인
2. **API 및 서비스 → 사용자 인증 정보**(또는 Google Auth Platform → **클라이언트**) → **+ 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
3. 애플리케이션 유형 **Android**, 이름 `clip-ferry android debug`
   - 패키지 이름: `app.clipferry.android`
   - SHA-1 인증서 디지털 지문: `03:5C:55:2D:30:BB:45:93:3D:19:E4:D1:DD:F8:2E:4E:31:27:B8:B8`
     (이 PC의 디버그 키. `apps/android`에서 `.\gradlew.bat signingReport`의 `Variant: debug` → `SHA1:`로 다시 볼 수 있다)
   - 맞춤 URI 스킴·앱 체크 같은 다른 칸은 그대로 둔다 → **만들기**
4. 만들어진 클라이언트 ID는 **어디에도 넣지 않는다**(서버에도 앱에도). 적어 둘 필요도 없다.
5. **OAuth 동의 화면 → 대상(테스트 사용자)**에 폰에서 쓸 구글 계정이 있는지 본다. 없으면 **+ Add users**.

- [x] 클라이언트 목록에 유형 "Android"인 `clip-ferry android debug`가 있다
- [x] 폰의 구글 계정이 테스트 사용자에 있다
- 참고: 콘솔 변경은 몇 분 뒤에 적용될 수 있다. 3절에서 `Developer console is not set up correctly`가 나오면 5분쯤 기다렸다 다시 한다.

## 1. Pi: 계정 서버를 이 브랜치로 다시 빌드

**Pi에서** (SSH):
```bash
cd ~/clip-ferry && git fetch && git checkout f35-android-login && git pull
grep CF_GOOGLE_CLIENT_IDS deploy/.env.account
```
- [x] `CF_GOOGLE_CLIENT_IDS=459283262663-4raksn21of8l1ltsd9t413fa3oav4sak.apps.googleusercontent.com`처럼 **웹 클라이언트 ID가 맨 앞**이다. Android 앱은 이 값을 받는다. (데스크톱 클라이언트 `…n607bs5v…`가 맨 앞이면 순서를 바꾸거나, 파일 끝에 `CF_GOOGLE_WEB_CLIENT_ID=<웹 클라이언트 ID>` 한 줄을 넣는다)

그다음 다시 빌드한다(Pi에서 10~20분). **릴레이(`compose.yml`)는 다시 올리지 않는다.**
```bash
docker compose --env-file deploy/.env.account -f deploy/compose.account.yml up -d --build
docker compose --env-file deploy/.env.account -f deploy/compose.account.yml logs account | grep -i "android\|desktop"
curl -s https://raspberry-pi.tailb6b7a3.ts.net:8443/v1/auth/google/android; echo
```
- [x] `logs … | grep` 명령이 아무것도 출력하지 않는다(`no google web client; android login is disabled` 경고가 없다)
- [x] `curl`이 `{"client_id":"459283262663-4raksn21of8l1ltsd9t413fa3oav4sak.apps.googleusercontent.com"}`(웹 클라이언트 ID)

## 2. 폰에 이 브랜치 앱 설치

폰을 USB로 PC에 꽂고(USB 디버깅은 F15 때 켜 둔 그대로), **PowerShell에서**:
```powershell
cd C:\Users\jonghyeok\Documents\clip-ferry
git checkout f35-android-login
git pull
.\scripts\build-android-core.ps1
cd apps\android
.\gradlew.bat installDebug
```
- 첫 줄 `build-android-core.ps1`은 5~15분 걸린다. 마지막에 `완료: apps/android/app/src/main/jniLibs, …`
- [x] ~~`installDebug`~~ → `installRelease`(배포 키, versionCode 5)로 `Installed on 1 device.` ("시험 중 나온 것" 1)
- `INSTALL_FAILED_UPDATE_INCOMPATIBLE`(서명이 다름)가 나오면 **앱을 지우지 말고** 멈춘다. 지우면 폰의 그룹이 사라진다. "막히면" 표를 본다.

## 3. 업데이트한 폰 = 기존 사용자 (그룹 유지 + 로그인)

PC의 설치된 clip-ferry는 켜 둔다(예전 버전, Pi 릴레이).

1. 폰에서 clip-ferry를 연다
   - [x] 제목 `clip-ferry 로그인`, 설명 `다시 로그인하면 이 기기의 그룹과 페어링은 그대로 이어서 씁니다.`, 버튼 `Google로 로그인`, 그 아래 `서버 설정`
   - 개발용 로그인 칸은 **없다**(배포 키 release 빌드로 설치했기 때문. "시험 중 나온 것" 1 참고)
   - [x] 위에서 내려 알림창을 보면 clip-ferry 상시 알림이 **없다**(연결하지 않음)
2. 로그인 전 타일·공유
   - 빠른 설정 패널을 내린다
   - [x] clip-ferry 타일이 꺼진 모양이다(보조 글씨가 보이는 기기면 `로그인 필요`)
   - [x] 아무 텍스트를 복사하고 타일을 누르면 토스트 `먼저 clip-ferry 앱에서 로그인하세요`
3. `서버 설정` → 계정 서버 주소 칸을 지우고 `https://raspberry-pi.tailb6b7a3.ts.net:8443` → `저장`
   - [x] 칸 아래 `저장했습니다`
4. `Google로 로그인`
   - [x] 화면 아래에서 구글 계정 선택 시트가 올라온다(브라우저가 아니다)
   - 테스트 사용자 계정을 고른다. 처음이면 `clip-ferry에 로그인`·권한 안내가 나온다 → **계속**
   - [x] 시트가 닫히고 **시작하기 화면이 아니라** 원래 메인 화면(`연결됨`, 기기 목록에 PC 포함)이 나온다. `연결됨`까지 몇 초 걸릴 수 있다
   - [x] 화면 맨 아래 `계정` 칸에 `내 이름 · 내 이메일`, `계정 서버: https://raspberry-pi.tailb6b7a3.ts.net:8443`, `로그아웃` 버튼
   - [x] 알림창에 상시 알림 `연결됨 · 온라인 2대`(또는 `연결됨`)가 다시 있다
5. 회귀 확인 (F17~F19, PC는 설치된 예전 앱)
   - [x] PC에서 아무 글이나 복사 → 폰 메모 앱에서 붙여넣기 하면 그 글
   - [x] PC에서 스크린샷(Win+Shift+S) → 폰 카카오톡 등에서 이미지 붙여넣기
   - [x] 폰에서 텍스트 복사 → 빠른 설정 타일 → PC에서 Ctrl+V 하면 그 글
   - [x] 폰에서 텍스트 복사 → 상시 알림의 `클립보드 보내기` → PC에서 붙여넣기
   - [x] 갤러리에서 사진 하나 → 공유 → `다른 기기로 보내기` → PC에서 붙여넣기 하면 그 사진
6. (선택) DB 클라이언트(`deploy/README.md` "DB 클라이언트로 접속")로 `devices` 표에 이 폰이 platform `android`로 있다

## 4. 다시 켜도 로그인이 유지된다

1. 폰 설정 → 애플리케이션 → clip-ferry → **강제 중지**
2. clip-ferry를 다시 연다
   - [x] 로그인 화면 **없이** 바로 메인 화면, 잠시 뒤 `연결됨`
   - [x] 구글 계정 선택 시트가 뜨지 않는다
3. 폰을 재부팅하고(선택) 앱을 열어도 같다

## 5. 로그아웃 · 취소 · 서버 오류

1. **로그아웃**: 메인 화면 맨 아래 `계정` → `로그아웃` → 대화상자 `로그아웃`
   - [x] 로그인 화면으로 바뀌고 설명이 `다시 로그인하면 이 기기의 그룹과 페어링은 그대로 이어서 씁니다.`
   - [x] 상시 알림이 사라진다
   - [x] 텍스트를 복사하고 타일 → 토스트 `먼저 clip-ferry 앱에서 로그인하세요`
   - [x] 갤러리 → 공유 → `다른 기기로 보내기` → 같은 토스트
   - [x] PC(설치된 앱)의 기기 목록에서 폰이 `오프라인`(바로 안 바뀌면 몇 초)
2. **구글 창에서 취소**: `Google로 로그인` → 계정 선택 시트가 뜨면 바깥(어두운 곳)을 누르거나 뒤로 가기
   - [x] 빨간 글씨 `로그인을 취소했습니다`, 다시 `Google로 로그인` 버튼
3. **계정 서버에 닿지 않을 때**: `서버 설정` → 주소를 `https://raspberry-pi.tailb6b7a3.ts.net:9999`로 저장 → `Google로 로그인`
   - [x] 구글 시트가 뜨지 않고 빨간 글씨 `계정 서버(https://raspberry-pi.tailb6b7a3.ts.net:9999)에 연결하지 못했습니다`
   - 주소를 `https://raspberry-pi.tailb6b7a3.ts.net:8443`로 되돌려 저장한다
4. **다시 로그인**: `Google로 로그인` → 같은 계정
   - [x] 바로 메인 화면, `연결됨`, 그룹·기기 목록 그대로(시작하기 화면이 아님)
   - [x] PC 목록에서 폰이 다시 `온라인`

## 6. (선택) 토큰을 확인하는 릴레이로 붙는지

폰이 접속 토큰을 실제로 싣는지 본다. PC에 토큰을 확인하는 릴레이를 띄우고 폰만 잠깐 그쪽으로 붙였다가 되돌린다. 그동안 PC(설치된 앱)와 폰은 서로 안 보인다(정상).

1. PC에서 Tailscale IP를 본다(PowerShell): `tailscale ip -4` → `100.…` 적어 둔다
2. 새 PowerShell 창(창 R):
   ```powershell
   cd C:\Users\jonghyeok\Documents\clip-ferry
   cargo run -q -p clip-ferry-relay -- --listen 0.0.0.0:8787 --account-url https://raspberry-pi.tailb6b7a3.ts.net:8443
   ```
   - Windows 방화벽 창이 뜨면 **허용**
   - [x] `access tokens required (account server set)`, `listening on 0.0.0.0:8787`
3. 폰 메인 화면의 `릴레이 주소` 칸: 지금 값(`wss://raspberry-pi.tailb6b7a3.ts.net` 등)을 **적어 둔다** → `ws://<1의 IP>:8787`로 바꾸고 `저장하고 다시 연결`
   - [x] 폰이 `연결됨`(온라인 1대 — 폰 혼자)
   - [x] 1분 뒤 창 R의 집계 줄이 `open=1`, `unauthorized=0`
4. 되돌리기: 폰 릴레이 주소를 3에서 적어 둔 값으로 바꾸고 `저장하고 다시 연결` → `연결됨 · 온라인 2대`. 창 R은 Ctrl+C

| `installDebug`가 `no connected devices` | USB 디버깅 연결 안 됨 | 폰의 "USB 디버깅 허용" 창에서 허용, 케이블 다시 |
| 로그인 뒤 `재연결 중`이 계속 | Pi 릴레이에 닿지 않는다(로그인과 무관) | 폰 Tailscale, 릴레이 주소 확인 |
| 6절에서 폰이 `재연결 중`만 | PC 방화벽이 8787을 막는다 | Windows 보안 → 방화벽 → 앱 허용에서 `clip-ferry-relay` 허용(개인·공용) |

## 시험 중 나온 것

1. (2026-11-08) 2절 `installDebug` → `INSTALL_FAILED_VERSION_DOWNGRADE: Update version code 1 is older than current 4`. 폰의 앱은 F31 때 GitHub Releases에서 받은 배포 APK(versionCode 4, 배포 키 SHA-1 `78:5E:1C:33:7F:C8:F7:B3:78:A1:75:50:41:5D:3B:6E:BE:81:60:9A`)였다. 디버그 키와 서명이 달라 디버그 빌드로는 업데이트할 수 없다(지우면 그룹이 사라짐).
   - 대신 배포 키로 서명한 release 빌드를 versionCode 5로 설치했다(업데이트로 설치, `firstInstallTime` 그대로 → 그룹 유지):
     ```powershell
     $k="$env:USERPROFILE\.clip-ferry-release"
     $env:CLIPFERRY_KEYSTORE="$k\release.jks"
     $env:CLIPFERRY_KEYSTORE_PASSWORD=(Get-Content "$k\password.txt" -Raw).Trim()
     $env:CLIPFERRY_VERSION_CODE="5"; $env:CLIPFERRY_VERSION_NAME="0.1.0-f35"
     cd apps\android; .\gradlew.bat installRelease
     ```
   - 그래서 구글 콘솔에 **배포 키 SHA-1로 Android 클라이언트를 하나 더** 만들어야 로그인된다(0절과 같은 방법, 이름 `clip-ferry android release`, SHA-1만 위 값).
   - release 빌드라 3절 1의 개발용 로그인 칸은 보이지 않는다(정상).
   - 다음 Releases 태그는 versionCode가 `github.run_number`라 5보다 커야 폰에 업데이트된다.

## 알려진 사항

- 로그인에는 폰에 구글 Play 서비스가 있어야 한다(구글 계정 선택 창을 Play 서비스가 띄운다).
- 로그인할 때 계정 서버는 ID 토큰을 확인할 구글 공개키를 받는다(받아 둔 것을 한동안 다시 쓴다). 로그인 뒤 갱신에는 계정 서버만 있으면 된다.
- 계정 서버에 닿지 않는 동안에는 접속 토큰을 갱신하지 못한다. 토큰을 확인하는 릴레이에는 연결되지 않지만 로그아웃되지는 않고, 닿으면 다시 연결된다.
- 다른 곳에서 이 로그인이 끊기면(갱신 토큰 거절) 다음 연결 때 앱이 로그인 화면으로 돌아가고 `로그인이 만료되었습니다. 다시 로그인하세요`가 보인다. 이것은 자동 테스트(`rejected_refresh_signs_out_and_stops`)로 확인했다.
- 배포 APK(GitHub Releases)로 로그인하려면 배포 키 SHA-1로 Android 클라이언트를 하나 더 만들어야 한다(`deploy/README.md` 계정 서버 1절 6).

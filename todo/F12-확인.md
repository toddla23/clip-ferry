# F12. 이미지 동기화 (데스크톱) — 확인할 것

상태: `확인대기` (docs/05-progress.md)

## 먼저 알아둘 것

- **스크린샷·이미지를 복사하면 다른 기기 클립보드로 넘어간다.** 텍스트와 같은 방식(복사하면 자동)이다. 클립보드에 텍스트가 있으면 텍스트가 우선이고, 텍스트가 없고 이미지만 있을 때 이미지를 읽는다.
- **보낼 때**: 클립보드 비트맵을 PNG로 인코딩해 256 KiB 청크로 나누어 보낸다. 인코딩은 속도를 위해 "빠른 압축"이라 파일이 조금 클 수 있다.
- **20 MiB 초과**: PNG가 20 MiB(원본 바이트)를 넘으면 **보내지 않고 시스템 알림**("복사한 이미지가 … MiB라 20 MiB를 넘어 보내지 않았습니다")을 띄운다. 알림은 Windows 토스트이고, 개발 모드(`tauri dev`)에서는 보낸 이가 "Windows PowerShell"처럼 보일 수 있다(앱이 설치돼 있지 않아서).
- **받을 때**: 다 모이면 길이·청크 수·SHA-256을 확인하고, 헤더로 형식(PNG·JPEG·GIF·WebP)을 직접 확인해 비트맵으로 풀어 클립보드에 쓴다. 보낸 쪽이 알린 크기는 믿지 않는다. 가로·세로 16384 px, 픽셀 데이터 256 MiB를 넘는 이미지는 풀지 않고 버린다. JPEG의 회전 정보는 반영하고, GIF는 첫 프레임만 쓴다.
- **에코 방지**: 받아서 쓴 이미지는 다시 보내지 않는다. 이미지는 클립보드에 쓴 뒤 다시 읽으면 픽셀이 조금 달라질 수 있어서, 내용 해시 외에 **"우리가 쓴 직후의 클립보드 변경은 복사로 보지 않는" 규칙**을 추가했다(텍스트에도 적용).
- **릴레이 속도 제한 대응**: 릴레이는 연결당 초당 50프레임까지 받는다. 20 MiB는 81건이라 이 한도를 넘는데, 코어가 `RateLimited`를 받으면 50 ms 쉬고 같은 조각을 다시 보낸다(최대 100번). 청크는 한 건씩 응답을 받으며 순서대로 보낸다.
- **조립 규칙**(03-protocol 2.3): 한 기기당 동시 2개까지 조립, 60초 안에 다 안 오면 버림, 청크는 `ImageStart` 뒤라면 순서가 뒤바뀌어도 되고 `ImageStart`보다 먼저 온 청크는 버린다. 청크 하나라도 번호·길이가 틀리거나 같은 번호가 두 번 오면 그 전송 전체를 버린다. 이유는 `BadImage` 카운터로만 센다.
- **CLI(디버그용)**: `cf send-image <파일>` (PNG·JPEG·GIF·WebP, 20 MiB 이하), `cf listen`이 받은 이미지를 **현재 폴더의 `./received/<시각>-<보낸 기기 이름>.<확장자>`**에 저장한다. 파일 이름은 보낸 기기 이름에서 영문·숫자·`-`·`_` 외의 글자를 `_`로 바꾸므로 폴더 밖으로 나갈 수 없다.
- 이미지도 텍스트와 같은 민감 표시 설정(`sync_sensitive`)을 따른다.
- 모바일은 F12 범위 밖이다.

### 준비 (터미널 3개, 모두 저장소 루트 `C:\Users\jonghyeok\Documents\clip-ferry`에서 시작)

처음이면 UI를 한 번 빌드한다: `cd apps\desktop; npm install; npm run build; cd ..\..`

**터미널 A — 릴레이**

**터미널 B — 데스크톱 앱** (처음 켜면 마법사: 이름을 정하고 `새 그룹 만들기`)

이미 `pc1` 프로필로 그룹을 만들어 두었다면 그대로 켜면 된다. 그룹이 꼬였으면 아래 "정리"를 한 뒤 다시 시작한다.

**터미널 C — CLI 기기 `x`** (앱에 페어링하고 `listen`)
1. 앱에서 `기기 추가`를 누르면 53자 코드가 뜬다. 터미널 C에서(처음 한 번만):
```powershell
cargo run -q -p clip-ferry-cli -- --profile x init --name cli-x
cargo run -q -p clip-ferry-cli -- --profile x join <앱에 뜬 코드>
```
   `이미 초기화된 기기입니다` 또는 `이미 그룹이 있습니다` 오류가 나면 `x`가 예전 그룹에 속해 있는 것이다. 터미널 C의 `listen`을 `Ctrl+C`로 끄고 `Remove-Item -Recurse -Force .cf-profiles\x`로 지운 뒤 `init`부터 다시 한다. 앱을 새로 만들었다면(마법사부터 다시) `x`도 항상 새로 만들어야 한다. 초대 코드는 10분이 지나면 만료되니 `기기 추가`로 새 코드를 받는다.
2. 앱에 뜬 6자리 숫자와 터미널 C의 숫자가 같으면 앱에서 `같음, 승인`, 터미널 C에서 `y`. 앱에 기기가 2대로 보이면 페어링 끝이다(이미 해 두었다면 건너뛴다).
3. 같은 터미널 C(저장소 루트)에서 `listen`을 켜 둔다. 받은 이미지는 **현재 폴더 아래 `received\`**, 즉 `C:\Users\jonghyeok\Documents\clip-ferry\received\`에 저장된다(`.gitignore`에 있어 커밋되지 않는다). **폴더를 옮기지 말 것**: CLI 프로필(`.cf-profiles\x`)도 현재 폴더 기준이라서 다른 폴더에서 실행하면 `x`를 못 찾는다.
```powershell
cargo run -q -p clip-ferry-cli -- --profile x listen
```
`connected`가 뜨면 준비 끝이다. 이후 `send-image`는 **터미널 D(새 터미널, 저장소 루트)**에서 실행한다.

## 참고

- 구조: 코어 `transfer.rs`(분할·조립·머리말 판별) → `ClipFerry::seal_image` / `handle_deliver`의 `Incoming::Image` → `Session::send_image` / `EventSink::on_image`. 데스크톱은 `clipsync.rs`(텍스트·이미지 공통 감시·에코 방지), `sysclip.rs`(`arboard` 이미지 읽기·쓰기), `imgcodec.rs`(PNG 인코딩, 형식·크기를 검사하는 디코딩), `shell.rs`(보내기·받기·알림).
- 새 의존성: `image 0.25`(png·jpeg·gif·webp만), `arboard`의 `image-data`, `tauri-plugin-notification`.
- 진행 표시(전송 중 UI)는 없다. 큰 이미지는 몇 초 걸릴 수 있다. 개발용(debug) 빌드는 PNG 인코딩이 느리다(릴리스는 훨씬 빠르다).
- 받는 쪽이 이미지를 풀 수 없으면(깨짐·한도 초과) 조용히 버린다.

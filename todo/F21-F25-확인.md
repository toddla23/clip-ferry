# F21~F25. iOS 앱 (M4) — 확인할 것 (Mac 빌려서 한 번에)

상태: `진행중` (docs/05-progress.md). 브랜치 `ios-m4` (`release-packaging` 위). Mac이 없어 iOS는 **CI(macOS)에서 컴파일만 확인**했다. 실제 동작은 아래에서 처음 본다.

F21~F25를 한 번에 확인하려고 문서 하나로 묶었다. 순서대로 하면 1~2시간이다. 막히는 곳은 "시험 중 나온 것"에 적고 다음 칸으로 넘어간다.

## 먼저 알아둘 것

- 범위
  - F21 앱 셸·페어링(코드 입력·QR)·앱이 열려 있을 때 받기(텍스트·이미지 → 클립보드)
  - F22 앱이 꺼져 있을 때 텍스트 → 알림(미리보기) → 누르면 클립보드. 릴레이 APNs 게이트웨이, 알림 확장(NSE)
  - F23 "clip-ferry로 클립보드 보내기" 단축어 동작, 뒷면 탭, 제어 센터 버튼(iOS 18+)
  - F24 공유 시트에서 보내기(사진·Safari)
  - F25 앱이 꺼져 있을 때 이미지 → 알림 → 누르면 보낸 PC가 다시 보낸다(서버 저장 없음, D-016)
- **PC 데스크톱 앱도 이 브랜치로 새로 빌드해야 한다.** 보내는 쪽 코어가 푸시 대상을 붙이고 재전송 요청에 답하게 바뀌었다. 옛 데스크톱 앱에서 보내면 아이폰에 푸시가 가지 않는다.
- 이미 해 둔 것(Windows): 코어·릴레이·FFI 테스트 통과(푸시 대상 선택, 가짜 푸시 서버로 "오프라인 아이폰 → 푸시 봉투 열기 → 이미지 재전송 요청 → 받음"까지 실제 릴레이로 확인). clippy 경고 없음. iOS 앱은 CI에서 시뮬레이터 빌드 성공.
- 시뮬레이터에서 안 되는 것: 카메라(QR 스캔 → 코드 입력으로 대신), 뒷면 탭(→ 단축어 앱에서 실행으로 대신). 실제 푸시는 **Apple Silicon Mac + 개발자 계정**이면 시뮬레이터에서도 온다.

## 0. 준비

### 계정·키 (Mac 빌리기 전에 해 두면 좋다)

- [ ] Apple Developer Program 가입(연 $99)
- [ ] APNs 키(.p8) 만들기, Key ID·팀 ID 적기 — `deploy/README.md` "iOS 푸시 켜기" 1번
- [ ] Pi 릴레이에 APNs 켜기 — 같은 절 2~4번. 로그에 `push gateway: apns`
  - `git pull`로 이 브랜치의 릴레이를 받아야 한다: Pi에서 `git fetch && git checkout ios-m4`

### Mac

- macOS 14 이상, **Xcode 16 이상**(제어 센터 버튼은 iOS 18 SDK가 필요). Apple Silicon이면 시뮬레이터에서도 실제 푸시가 온다.
- 설치:
  ```sh
  xcode-select --install                     # 이미 있으면 건너뜀
  /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
  brew install xcodegen
  curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
  source "$HOME/.cargo/env"
  rustup target add aarch64-apple-ios aarch64-apple-ios-sim x86_64-apple-ios
  ```
- [ ] **Tailscale**을 Mac에 깔고 같은 계정으로 로그인(릴레이가 Tailscale 안에 있다). 시뮬레이터는 Mac의 네트워크를 쓴다.

## 1. 빌드·실행

```sh
git clone https://github.com/toddla23/clip-ferry.git && cd clip-ferry
git checkout ios-m4
./scripts/build-ios-core.sh            # 5~10분. apps/ios/Core/에 xcframework와 Swift 바인딩
cd apps/ios && xcodegen generate && open ClipFerry.xcodeproj
```

- [ ] Xcode → 왼쪽 맨 위 `ClipFerry` 프로젝트 → 타깃 4개(ClipFerry, ClipFerryNotify, ClipFerryShare, ClipFerryWidgets) 각각 **Signing & Capabilities → Team**에 내 팀을 고른다
  - 번들 ID `app.clipferry.ios`·`.notify`·`.share`·`.widgets`, App Group `group.app.clipferry`, Push Notifications가 자동으로 등록된다. 빨간 오류가 있으면 메시지를 적는다
  - 팀 없이(계정 없이) 하려면: 시뮬레이터 + "Sign to Run Locally". 푸시(3·7절)는 건너뛴다
- [ ] 위쪽 실행 대상을 **iPhone 16 (iOS 18) 시뮬레이터**로 고르고 ▶ 실행 → 앱이 뜬다
- [ ] 첫 화면에서 기기 이름(예: `iPhone 시뮬`) → 다음

## 2. 페어링·앱 열려 있을 때 받기 (F21)

1. PC 데스크톱 앱(이 브랜치로 새로 빌드)에서 릴레이 주소를 확인하고 `기기 추가` → 코드가 뜬다.
2. 아이폰 앱 첫 화면 아래 `릴레이 주소`에 PC와 같은 주소(예: `wss://<Pi>.ts.net`)를 넣고 `저장`. (QR로 참여하면 QR 안의 주소를 쓰지만, 코드에는 주소가 없을 수 있다.)
3. 아이폰 앱: `QR 스캔 또는 코드 입력` → 코드 칸에 PC 코드를 붙여넣기(Mac에서 복사 → 시뮬레이터에 Cmd+V) → `참여`.

- [ ] 양쪽에 같은 숫자가 뜨고, PC에서 승인하면 아이폰에 `그룹에 참여했습니다`
- [ ] 메인 화면 `연결됨 · 온라인 2대`, 기기 목록에 PC와 이 기기(초록 점)
- [ ] 앱을 연 채로 PC에서 텍스트 복사 → 아이폰 화면 아래 `…에서 텍스트를 받았습니다` → 메모 앱에 붙여넣으면 같은 글(한글·이모지)
- [ ] PC에서 스크린샷 복사 → 아이폰 메모에 붙여넣으면 같은 이미지
- [ ] 알림 허용 팝업이 뜨면 **허용**
- [ ] (선택, 실기기) QR 스캔으로도 참여된다
- [ ] (선택) 반대로 아이폰에서 `기기 추가` → PC/Android가 그 코드로 참여

## 3. 앱이 꺼져 있을 때 텍스트 → 알림 (F22)

1. 아이폰 앱을 완전히 끈다(앱 전환기에서 위로 밀기, 시뮬레이터는 Cmd+Shift+H 두 번 → 위로).
2. PC에서 텍스트를 복사한다.

- [ ] 몇 초 안에 알림: 제목 = PC 이름, 본문 = 복사한 글 미리보기
- [ ] 알림을 누르면 앱이 열리고 `…클립보드에 넣었습니다` → 메모에 붙여넣으면 같은 글
- [ ] 앱 설정에서 `알림에 받은 텍스트 미리보기` 끄고 다시 → 본문이 `텍스트가 도착했습니다 — 눌러서 붙여넣기`
- [ ] 긴 글(2,000자 넘게) 복사 → `긴 내용이 도착했습니다 — 눌러서 받기` → 누르면 PC가 다시 보내 붙여넣기 된다(PC가 켜져 있어야 함)
- [ ] **NSE 메모리**: Xcode → Debug → Attach to Process by PID or Name → `ClipFerryNotify` → 알림이 올 때 Debug navigator(⌘7)의 Memory 값을 적는다(24 MB 이하여야 함): ______ MB
- [ ] **복호화 실패 대체**: 터미널에서 가짜 푸시를 넣는다. 일반 문구 `새 클립이 도착했습니다`가 뜨고 크래시가 없다.
  ```sh
  cat > /tmp/bad.json <<'JSON'
  {"aps":{"alert":{"title":"clip-ferry","body":"새 클립이 도착했습니다"},"mutable-content":1},"p":"AAAA"}
  JSON
  xcrun simctl push booted app.clipferry.ios /tmp/bad.json
  ```
- [ ] 앱이 열려 있을 때는 알림 없이 바로 받는다(2절과 같음)

## 4. 보내기: 단축어·뒷면 탭·제어 센터 (F23)

- [ ] 단축어 앱 → `+` → 동작 검색 `clip-ferry` → **클립보드 보내기**가 보인다. (앱 단축어 목록에 `clip-ferry로 클립보드 보내기`도)
- [ ] Safari에서 글을 복사하고 단축어를 실행 → (처음엔 `붙여넣기 허용` 묻기 → 허용) → `텍스트를 다른 기기 1대로 보냈습니다` → PC 붙여넣기
- [ ] 이미지(사진 앱에서 복사)도 같은 결과
- [ ] 설정 → clip-ferry → 다른 앱에서 붙여넣기 → **허용** 후에는 묻지 않는다
- [ ] (실기기) 설정 → 손쉬운 사용 → 터치 → 뒷면 탭 → 이중 탭 → `클립보드 보내기` → 복사 후 뒷면 두 번 톡톡
- [ ] (iOS 18) 제어 센터 편집 → 컨트롤 추가 → clip-ferry `클립보드 보내기` → 눌러서 보내진다
  - 제어 센터에서 클립보드를 읽지 못하면(오류 문구) 그대로 적는다

## 5. 공유 시트 (F24)

- [ ] 사진 앱 → 사진 → 공유 → **clip-ferry** → `이미지를 다른 기기 1대로 보냈습니다` → 닫힘 → PC 붙여넣기
- [ ] Safari → 공유 → clip-ferry → PC에 페이지 주소
- [ ] 메모 앱에서 글을 선택 → 공유 → clip-ferry → PC에 그 글
- [ ] 큰 사진(수 MB)도 간다. 20 MiB 넘는 것은 `20 MiB를 넘거나…` 안내

## 6. 앱이 꺼져 있을 때 이미지 (F25)

1. 아이폰 앱을 끈다.
2. PC에서 스크린샷을 복사한다.

- [ ] 알림 `이미지가 도착했습니다 — 눌러서 받기`
- [ ] 누르면 앱이 열리고 `…다시 보내 달라고 요청하는 중…` → 몇 초 안에 `이미지를 받았습니다` → 메모에 붙여넣으면 같은 이미지
- [ ] PC 앱을 끈 상태에서 같은 알림을 누르면 `보낸 기기(…)가 오프라인입니다`
- [ ] 10분 넘게 지난 알림을 누르면(또는 PC에서 그 뒤에 다른 것을 복사했으면) 20초 뒤 `보낸 기기에 더 이상 남아 있지 않습니다…`

- 2026-11-05 (CI): 시뮬레이터 빌드는 성공. 빌드 중 `appintentsnltrainingprocessor: error: Unable to parse extract.actionsdata` 로그가 나온다(빌드는 안 막음). 4절에서 단축어 앱에 `클립보드 보내기`가 안 보이면 이것과 관련 있을 수 있으니 알려 달라.

## 알려진 사항

- iOS는 화면을 벗어나면 연결을 닫는다(곧 멈추므로). 그동안은 푸시로 받는다. 앱이 열려 있을 때만 바로 클립보드에 들어간다.
- 받는 쪽 알림을 누르기 전에는 클립보드에 넣지 못한다(iOS가 백그라운드 클립보드 쓰기를 막는다).
- 재전송은 보낸 기기가 켜져 있고 10분 안이며 그 뒤 다른 것을 보내지 않았을 때만 된다(D-016).
- 받은 텍스트 미리보기는 iOS 알림 센터에 남는다. 원치 않으면 미리보기를 끈다.
- 앱 기본 릴레이 주소는 개발용이다. 페어링하면 QR·코드에 든 릴레이 주소로 바뀐다.

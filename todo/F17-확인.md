# F17. Android 수신 → 클립보드 — 확인할 것

상태: `확인대기` (docs/05-progress.md). 브랜치 `f17-android-receive` (F16 브랜치 위).

**확인 결과 (2026-11-05, 사용자 보고)**: 1~6번 모두 통과. PC → 폰 텍스트(한글·이모지·여러 줄, 백그라운드 포함)·이미지(큰 스크린샷 포함) 붙여넣기, 캐시 최근 1개 유지·텍스트 뒤 비움(adb로 확인), 알림 끄기, 서비스 중지·재시작, 화면 꺼짐 상태 수신.

## 먼저 알아둘 것

- 이번 범위:
  - PC에서 복사한 **텍스트·이미지가 폰 클립보드에 바로 들어간다**.
  - 앱이 백그라운드에 있어도 된다. 상시 알림(연결 유지 서비스)이 떠 있으면 받는다.
  - 받으면 알림을 띄운다(`받은 클립보드` 카드의 스위치로 끌 수 있음). 알림에는 보낸 기기 이름과 종류만 있고 **내용은 없다**.
- 폰에서 PC로 보내기는 아직 없다(F18 타일·알림 버튼).
- 이미지는 앱 캐시(`cache/received/`)에 파일로 두고 그 주소를 클립보드에 넣는다.
  - 붙여넣는 앱은 클립보드가 주는 임시 권한으로만 그 파일을 읽는다.
  - 캐시에는 가장 최근 것 하나만 남는다. 새 이미지나 텍스트를 받으면 이전 이미지 파일은 지운다.
  - 이미지 형식은 보낸 쪽이 적은 값을 믿지 않고 코어가 머리말로 다시 확인한다(PNG·JPEG·GIF·WebP). 알 수 없으면 버린다.
- 안드로이드 13 이상은 다른 앱이 클립보드에 쓰면 화면 아래에 시스템 표시가 잠깐 뜬다. "다른 기기에서 온 내용" 표시를 붙여 둔다(`EXTRA_IS_REMOTE_DEVICE`).
- 텍스트가 아주 크면(약 수십만 자 이상) 안드로이드의 전달 한도에 걸려 클립보드에 넣지 못할 수 있다. 그때는 앱이 죽지 않고 `너무 커서 넣지 못했습니다` 알림을 띄운다.
- 이미 해 둔 것(Windows):
  - FFI 테스트 11개 통과. 새 테스트는 실제 릴레이로 PC → 폰 텍스트(한글·이모지)와 이미지가 셸 콜백까지 오는지, 보낸 쪽이 형식을 틀리게 적어도 실제 형식이 가는지, 형식을 알 수 없는 바이트는 오지 않는지 본다.
  - `.so`와 Kotlin 바인딩을 만들었고 `assembleDebug`가 성공했다.

## 0. 준비

- 폰: USB 디버깅 연결, **Tailscale 켜기**.
- PC: 평소 데스크톱 앱(`pc1` 프로필)이 `연결됨`이고 폰과 같은 그룹이다(F16에서 페어링한 상태).
  - 그룹이 풀렸으면 F16 3번처럼 QR로 다시 참여한다.

## 1. 빌드·설치 (PC, PowerShell)

F16 앱 위에 그대로 덮어 깐다(그룹이 유지된다).

```powershell
cd C:\Users\jonghyeok\Documents\clip-ferry
git checkout f17-android-receive
.\scripts\build-android-core.ps1
cd apps\android
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
.\gradlew.bat installDebug
cd ..\..
```

- [x] `installDebug`가 `BUILD SUCCESSFUL`이다
- [x] 앱을 열면 메인 화면에 `받은 클립보드` 카드가 있고 `아직 받은 것이 없습니다`, `받으면 알림 띄우기`(켜짐)가 보인다
- [x] `연결됨`이고 기기 목록에서 PC가 초록 점이다

## 2. 텍스트 (완료 조건 1)

1. PC 메모장에서 `안녕 clip-ferry 📋 테스트`를 복사한다.

- [x] 폰에 `'<PC 이름>'에서 받은 텍스트를 클립보드에 넣었습니다` 알림이 뜬다(15초 뒤 사라진다)
- [x] 폰 메모 앱 등에서 길게 눌러 `붙여넣기` → 같은 글이 들어간다(한글·이모지 포함)
- [x] 앱의 `받은 클립보드` 카드에 `<시각> · '<PC 이름>'에서 받은 텍스트`가 보인다

2. 앱을 **백그라운드로** 보낸다(홈 버튼). 최근 앱에서 지워도 된다(상시 알림은 남아 있어야 한다).
3. PC에서 다른 글을 복사한다.

- [x] 폰 다른 앱에서 붙여넣으면 새 글이 들어간다
- [x] 여러 줄 텍스트도 줄바꿈 그대로 들어간다

## 3. 이미지 (완료 조건 2)

1. PC에서 스크린샷을 찍는다(Win+Shift+S로 영역 선택).

- [x] 폰에 `받은 이미지를 클립보드에 넣었습니다` 알림이 뜬다
- [x] 이미지 붙여넣기를 지원하는 앱에서 붙여넣으면 같은 이미지가 들어간다
  - 예: 카카오톡 입력창 길게 누르기 → 붙여넣기, Gboard 클립보드 목록, 삼성 노트/Google Keep 등
  - 앱마다 이미지 붙여넣기 지원이 다르다. 안 되는 앱이 있으면 이름을 적어 달라
- [x] 큰 스크린샷(전체 화면, 수 MB)도 몇 초 안에 들어간다

## 4. 캐시가 하나만 남는다 (완료 조건 3)

1. PC에서 스크린샷을 두 번 더 복사한다. 그다음 텍스트를 하나 복사한다.
2. PowerShell에서 폰 앱 캐시를 본다.

   ```powershell
   & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" shell run-as app.clipferry.android ls -l cache/received
   ```

- [x] 이미지를 받은 직후에는 파일이 **하나**만 있다(`clip-<숫자>.png`)
- [x] 텍스트를 받은 뒤에는 **비어 있다**

## 5. 알림 끄기

- [x] `받으면 알림 띄우기`를 끄고 PC에서 복사하면 알림 없이 클립보드에만 들어간다(카드의 시각은 바뀐다)
- [x] 다시 켜 둔다

## 6. 그 밖의 경우

- [x] PC 데스크톱 설정에서 `보내기`가 꺼져 있으면 폰에 오지 않는다(데스크톱 쪽 동작 확인)
- [x] 폰 알림의 `중지`로 서비스를 끄면 PC에서 복사해도 오지 않는다. 다시 켜면 그 뒤 복사한 것부터 온다(꺼져 있던 동안 것은 오지 않는다. 서버는 저장하지 않는다)
  - 다시 켠 뒤에는 **새 내용**을 복사해서 본다. 데스크톱은 직전에 보낸 것과 같은 내용을 다시 복사하면 보내지 않는다(F11 에코 방지). 폰이 꺼져 있어 못 받았어도 같다
- [x] 폰 화면이 꺼져 있을 때 PC에서 복사하고, 폰을 켜서 붙여넣으면 들어간다(배터리 최적화 예외 상태에서)

## 시험 중 나온 것

- 2026-11-05: 서비스를 중지했다가 다시 켠 뒤 PC에서 복사했는데 오지 않았다. 중지 중에 복사했던 것과 같은 내용을 다시 복사해서, 데스크톱이 이미 보낸 것으로 보고 보내지 않은 것이었다. 새 내용은 정상으로 왔다(폰 쪽 문제 아님).

## 알려진 사항 (이번 범위 밖)

- 폰 → PC 보내기는 F18(타일·알림 버튼)·F19(공유·텍스트 선택 메뉴).
- 앱 프로세스가 죽어 있으면(강제 종료) 받지 못한다. 푸시로 깨우기는 F20.
- 받기를 끄는 설정은 없다. 데스크톱에서 보내기를 끄거나 폰의 연결을 중지한다.

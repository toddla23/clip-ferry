# F16. Android 페어링 — 확인할 것

상태: `진행중` (docs/05-progress.md). 브랜치 `f16-android-pairing`. 실기기 확인 전이다.

## 먼저 알아둘 것

- 이번 범위:
  - 폰에서 데스크톱 QR을 스캔하거나 코드를 입력해 그룹에 참여한다.
  - 폰이 초대(QR과 코드)하고 다른 기기가 참여한다.
  - 양쪽 6자리 확인 숫자를 비교한다.
  - 첫 실행 화면을 바꿨다(이름, `QR로 참여`, `코드 입력으로 참여`, `새 그룹 만들기`).
  - 기기 목록은 보기만 한다(온라인 표시 포함).
- 클립보드 주고받기는 아직 없다(F17~).
- F15 앱은 처음 켤 때 **혼자인 그룹을 자동으로 만들었다.** 이번부터는 만들지 않고 첫 실행 화면을 보여 준다.
  - 이미 F15 앱이 깔려 있으면 혼자인 그룹이 남아 있다.
  - 이 경우 메인 화면에 `다른 그룹에 참여` 카드가 보인다. 아래 1번처럼 앱을 지우고 새로 깔아도 된다.
- QR에는 초대한 기기의 릴레이 주소가 들어 있다.
  - QR로 참여하면 폰의 릴레이 주소가 **그 주소로 바뀐다.**
  - 코드 입력으로 참여하면 폰에 저장된 릴레이 주소를 쓴다.
- QR 인식은 기기 안(ML Kit 번들 모델)에서만 한다. 카메라 영상은 어디에도 보내지 않는다.
- 이미 해 둔 것(Windows):
  - `cargo fmt`, `clippy`가 깨끗하다.
  - FFI 테스트 10개가 통과했다. 실제 릴레이로 QR 참여·확인 숫자 일치·승인·서로 온라인 표시, 텍스트 코드 참여·거절, 취소 뒤 늦은 알림 없음, 그룹 나가기를 돌렸다.
  - `.so`와 Kotlin 바인딩을 만들었고 `assembleDebug`가 성공했다.

## 0. 준비 (PC)

1. 환경 변수 `ANDROID_HOME`, `ANDROID_NDK_HOME`은 이미 설정되어 있다. 새 PowerShell을 연다.
2. 폰을 준비한다.
   - USB 디버깅을 켜고 USB로 PC에 연결한다.
   - **Tailscale 앱**을 켜 둔다. Pi 릴레이 `wss://raspberry-pi.tailb6b7a3.ts.net`에 닿으려면 필요하다.
3. 확인 (PowerShell):

   ```powershell
   & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" devices
   ```

   → 기기가 `device`로 보인다. `unauthorized`면 폰의 팝업을 승인한다.
4. Pi 릴레이가 떠 있는지 확인한다.
   - 데스크톱 앱(평소 쓰는 것)이 `연결됨`이면 된다.
   - 데스크톱 앱의 릴레이 주소는 `wss://raspberry-pi.tailb6b7a3.ts.net`이어야 한다(설정에서 확인).

## 1. 빌드·설치 (PC, PowerShell, 저장소 루트)

깨끗한 첫 실행을 보려고 이전 앱을 먼저 지운다. 지우면 Keystore 키와 혼자인 그룹이 함께 사라진다.

```powershell
cd C:\Users\jonghyeok\Documents\clip-ferry
git checkout f16-android-pairing
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" uninstall app.clipferry.android
.\scripts\build-android-core.ps1
cd apps\android
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
.\gradlew.bat installDebug
cd ..\..
```

- [ ] `build-android-core.ps1`가 `완료`를 출력한다
- [ ] `installDebug`가 `BUILD SUCCESSFUL`이다. 카메라·ML Kit 라이브러리를 처음 받느라 몇 분 걸릴 수 있다

## 2. 첫 실행 화면 (폰)

1. 앱을 연다. 알림 권한 팝업이 뜨면 **허용**한다.

- [ ] `처음 설정` 화면이 보인다
  - `이 기기 이름`(폰 모델명이 미리 채워짐)
  - `QR로 참여`, `코드 입력으로 참여`, `새 그룹 만들기`
  - 아래에 `릴레이 주소` 카드
- [ ] 상단 알림창에 clip-ferry 상시 알림이 **없다**(그룹이 없으면 연결하지 않는다)

2. 릴레이 주소에 `wss://raspberry-pi.tailb6b7a3.ts.net`을 넣고 `저장`을 누른다. 코드 입력으로 참여할 때 쓰인다.
3. 이름을 원하는 대로 바꾼다(예: `내 폰`).

## 3. 데스크톱 QR로 참여 (완료 조건 1-가)

1. 데스크톱 앱(평소 쓰는 것)에서 `기기 추가`를 누른다. QR, 코드, 남은 시간이 뜬다.
2. 폰에서 `QR로 참여`를 누르면 카메라 권한 팝업이 뜬다. **허용**한다.
3. 데스크톱 화면의 QR을 폰 카메라로 비춘다.

- [ ] 폰이 QR을 읽으면 `그룹에 참여` 화면으로 넘어간다
  - `'<데스크톱 이름>'의 그룹에 참여합니다`
  - 6자리 숫자(3자리씩 띄움)
  - `승인을 기다리는 중…`
- [ ] 데스크톱에 `참여 요청`이 뜨고, `<폰 이름>`과 **같은 6자리 숫자**가 보인다
- [ ] 데스크톱에서 `같음, 승인`을 누른다
  - 데스크톱은 `기기를 추가했습니다`
  - 폰은 바로 메인 화면으로 넘어가고, 곧 `연결됨`이 된다
- [ ] 폰 메인 화면
  - `에포크 1 · 구성원 2대`(데스크톱 그룹의 에포크에 따라 숫자는 다를 수 있다)
  - `기기 2대` 목록에 데스크톱과 `<폰 이름> (이 기기)`가 둘 다 초록 점(`연결됨`)
- [ ] 폰 상단 알림이 `연결됨 · 온라인 2대`다
- [ ] 데스크톱 기기 목록에 폰이 보이고 온라인으로 표시된다
- [ ] 폰의 `릴레이 주소` 카드가 데스크톱과 같은 주소다(QR의 주소로 바뀜)
- [ ] 데스크톱 앱을 끄면 폰 목록에서 데스크톱 점이 회색(`연결 안 됨`)이 된다. 다시 켜면 초록이 된다

## 4. 카메라 권한 거부 → 코드 입력 안내 (완료 조건 2)

같은 폰에서 다시 해 보려면 그룹에서 나와야 한다.

1. 데스크톱에서 폰을 **제거**한다.
2. 폰에 `그룹에서 제거됨`과 `다시 페어링` 카드가 뜬다. `그룹 나가고 다시 페어링` → `나가기`를 누른다.
   - 데스크톱에서 제거하지 않고 앱을 지워도 된다(1번의 `uninstall`과 `installDebug`).
   - 이렇게 하면 데스크톱 목록에 옛 폰이 남으므로 데스크톱에서 지운다.
3. 카메라 권한을 끈다: 폰 설정 → 앱 → clip-ferry → 권한 → 카메라 → **허용 안함**.
   - 앱을 새로 깔았다면 다음 단계의 팝업에서 `허용 안함`을 누른다.

- [ ] 폰이 `처음 설정` 화면으로 돌아와 있다. 이름은 그대로다(기기 키는 유지된다)
- [ ] `QR로 참여`를 누르면 권한 팝업이 뜨거나, 이미 거부했으면 팝업 없이 바로 `코드 입력으로 참여` 화면으로 바뀐다. 이때 `카메라 권한이 없어 QR을 스캔할 수 없습니다…` 안내 카드가 보인다
- [ ] 데스크톱에서 `기기 추가` → 코드를 폰에 입력한다
  - 길다. 데스크톱의 코드를 메모 앱 등으로 옮겨 붙여넣어도 된다.
  - 소문자나 하이픈이 빠져도 된다.
  - `참여`를 누르면 3번과 같이 6자리 → 데스크톱 승인 → 연결된다
- [ ] 잘못된 코드(예: `ABCD`)를 넣고 `참여`를 누르면 `초대 코드를 읽을 수 없습니다: …` 빨간 글씨가 뜨고 앱이 죽지 않는다

시험이 끝나면 카메라 권한을 다시 켜 둔다(설정 → 앱 → clip-ferry → 권한 → 카메라 → 앱 사용 중에만 허용).

## 5. 폰이 초대 → 데스크톱이 코드로 참여 (완료 조건 1-나)

평소 데스크톱 앱은 이미 그룹이 있어 참여할 수 없다. **두 번째 데스크톱 프로필**(`pc2`)로 시험한다.

1. 새 PowerShell을 열고 저장소 루트에서 두 번째 데스크톱 앱을 켠다. 평소 앱은 켜 둔 채로 둔다.

   ```powershell
   cd C:\Users\jonghyeok\Documents\clip-ferry
   cargo build -p clip-ferry-desktop
   $env:CF_DESKTOP_PROFILE="pc2"; $env:CF_RELAY="wss://raspberry-pi.tailb6b7a3.ts.net"; $env:WEBVIEW2_USER_DATA_FOLDER="$env:TEMP\wv-pc2"
   .\target\debug\clip-ferry-desktop.exe
   ```

   - `cargo build`가 UI 빌드를 하지 않아 화면이 비면 `cd apps\desktop; npm run tauri dev`로 켠다.
   - 같은 PowerShell에서 위 환경 변수를 먼저 설정한다.
2. `pc2` 앱에 `clip-ferry 시작하기`(마법사)가 뜬다. 이름을 `pc2`로 둔다.
3. 폰 메인 화면의 `기기 2대` 카드에서 `기기 추가`를 누른다.

- [ ] 폰에 `기기 추가` 화면이 뜬다
  - 흰 바탕 QR
  - 4자씩 묶인 코드
  - `남은 시간 m:ss`가 1초마다 줄어든다
- [ ] `pc2`에서 `코드로 참여` → 폰의 코드를 입력(직접 치거나 폰에서 PC로 옮겨 붙여넣기) → `참여`
- [ ] 폰에 `'pc2' 기기가 참여하려고 합니다`와 6자리가 뜨고, `pc2` 화면에도 같은 숫자가 보인다
- [ ] 폰에서 `승인` → 폰 `'pc2' 기기를 추가했습니다` → `닫기`
- [ ] 폰 목록이 `기기 3대`가 되고, 평소 데스크톱과 `pc2`가 모두 초록 점이다
- [ ] 평소 데스크톱 앱 목록에도 `pc2`가 보인다(폰이 구성원 변경을 알렸다)
- [ ] 거절도 한 번 해 본다. `pc2`를 데스크톱에서 제거한 뒤 아래 "정리"의 `pc2` 프로필 지우기를 하고 다시 켠다. 같은 순서로 하되 폰에서 `거절`을 누른다
  - 폰은 `참여 요청을 거절했습니다`
  - `pc2`는 `참여하지 못했습니다`

## 6. 그 밖의 경우

- [ ] 폰 초대 화면에서 `취소`나 뒤로 가기를 누르면 메인 화면으로 돌아온다. 그 코드로 참여를 시도하면 응답 없이 시간이 지나 실패한다(초대가 닫혔다)
- [ ] 초대를 띄워 두고 10분(초대 유효 시간)이 지나면 `페어링하지 못했습니다 / 초대가 만료되었습니다`가 뜬다. `새 초대`를 누르면 새 코드가 뜬다(선택, 오래 걸림)
- [ ] 참여 중(6자리 화면)에 폰에서 `취소`를 누르면 처음 설정 화면으로 돌아온다. 앱이 죽지 않는다
- [ ] 앱을 강제 종료하고 다시 열어도 그룹·기기 목록이 그대로이고 `연결됨`이 된다

## 알려진 사항 (이번 범위 밖)

- 폰에서 기기 제거·이름 변경은 없다(데스크톱에서 한다).
- 폰 이름은 처음 정한 뒤 바꿀 수 없다.
- 클립보드 주고받기는 F17~에서 한다.
- 데스크톱이 코드로 참여하면 자기 릴레이 설정을 쓴다. 텍스트 코드에는 릴레이 주소가 없어서다. 그룹의 모든 기기가 같은 릴레이여야 한다.
- 폰 초대 화면은 화면 꺼짐을 막지 않는다. 오래 걸리면 화면이 꺼질 수 있다.

## 정리

- 폰 앱 지우기 (PowerShell): `& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" uninstall app.clipferry.android`
  - Keystore 키와 저장 데이터가 함께 지워진다.
- `pc2` 프로필 지우기 (PowerShell): `pc2` 앱을 트레이에서 종료한 뒤

  ```powershell
  Remove-Item -Recurse -Force "$env:APPDATA\app.clipferry.desktop\profiles\pc2"
  cmdkey /list | Select-String clip-ferry-pc2
  ```

  `cmdkey /list`에 `clip-ferry-pc2` 항목이 남아 있으면 `cmdkey /delete:<그 이름>`으로 지운다.
- 평소 데스크톱 앱 목록에서 시험한 폰·`pc2`를 제거한다.

# F37. 계정으로 기기 연결 — 확인할 것

상태: `진행중` (docs/05-progress.md). 브랜치 `f37-account-link` (F35 완료 커밋 위).

이 문서만 보고 처음부터 끝까지 따라 할 수 있게 썼다. 각 단계는 **할 일 → 보여야 하는 것** 순서다. 다르게 보이면 맨 아래 "막히면"을 먼저 보고, 그래도 안 되면 그 화면·문구를 "시험 중 나온 것"에 적는다.

## 무엇을 시험하나

- 같은 구글 계정으로 로그인한 새 기기가 **QR·코드 없이** 그룹에 들어온다.
  - 새 기기: 첫 화면의 `이 계정의 다른 기기로 연결`
  - 기존 기기: `새 기기 연결 요청` 카드(+ 알림) → `연결` → 양쪽에 6자리 숫자 → 같으면 `승인`
- 숫자 확인은 그대로 남는다. 계정 서버가 중간에 끼어들면 양쪽 숫자가 달라지게 만들었다(D-022, 자동 테스트로 확인).
- 데스크톱 ↔ 데스크톱, 폰이 기존 기기(응답하는 쪽), 폰이 새 기기(요청하는 쪽)를 모두 본다.
- QR·코드 페어링은 그대로 된다.

## 시험 구성

```
Pi   계정 서버   https://raspberry-pi.tailb6b7a3.ts.net:8443   (이 브랜치로 다시 빌드)
Pi   릴레이      wss://raspberry-pi.tailb6b7a3.ts.net           (지금 그대로, 다시 올리지 않는다)
PC   설치된 clip-ferry (예전 버전)   — 지금 폰과 쓰는 진짜 그룹. 3·4절에서 기기 제거에 쓴다
PC   앱 A  프로필 f37a  (npm run tauri dev)            — 이 브랜치, 2절
PC   앱 B  프로필 f37b  (앱 A가 빌드한 exe 직접 실행)    — 이 브랜치, 2절
PC   앱 C  프로필 f37c  (npm run tauri dev)            — 이 브랜치, 3~5절
폰   clip-ferry  이 브랜치(배포 키 release 빌드, versionCode 6)
```

- **모든 기기는 같은 구글 계정으로 로그인한다.** 계정이 다르면 요청이 보이지 않는다(정상, 다른 계정 거부).
- **프로필**: `CF_DESKTOP_PROFILE`을 주면 데이터 폴더와 자격 증명 이름이 따로 생긴다. 설치된 앱의 데이터는 건드리지 않는다.
- 폰의 Tailscale은 켜 둔다.
- **창 R(F35 6절에서 띄운 `clip-ferry-relay`)이 아직 켜져 있으면 Ctrl+C로 끈다.** 켜져 있으면 PC에서 빌드가 `액세스가 거부되었습니다`로 실패한다.

## 1. Pi: 계정 서버를 이 브랜치로 다시 빌드

**Pi에서** (SSH):
```bash
cd ~/clip-ferry && git fetch && git checkout f37-account-link && git pull
docker compose --env-file deploy/.env.account -f deploy/compose.account.yml up -d --build
```
- 다시 빌드는 10~20분. **릴레이(`compose.yml`)는 다시 올리지 않는다.**

다 되면 (Pi에서):
```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST -H "Content-Type: application/json" -d '{"sign_pub":"","dh_pub":"","name":"x"}' https://raspberry-pi.tailb6b7a3.ts.net:8443/v1/link/ticket
```
- [x] `401` (새 경로가 있고, 로그인 없이는 확인서를 주지 않는다). `404`면 예전 코드가 돌고 있다 → 위 두 줄을 다시
  - 본문을 `{}`로 보내면 `422`가 나온다(본문 칸 검사가 로그인 확인보다 먼저다). 이것도 새 경로가 있다는 뜻이다

## 2. 데스크톱 ↔ 데스크톱 (앱 A는 기존 기기, 앱 B는 새 기기)

### 2-1. 앱 A 띄우기 (창 A, PowerShell)

```powershell
cd C:\Users\jonghyeok\Documents\clip-ferry
git checkout f37-account-link
git pull
cd apps\desktop
npm install
$env:CF_DESKTOP_PROFILE = "f37a"
$env:CF_RELAY = "wss://raspberry-pi.tailb6b7a3.ts.net"
$env:CF_ACCOUNT = "https://raspberry-pi.tailb6b7a3.ts.net:8443"
npm run tauri dev
```
- `CF_RELAY`·`CF_ACCOUNT`는 새 프로필의 기본 릴레이·계정 서버 주소다. 없으면 `127.0.0.1`이 기본이라 Pi에 붙지 않는다.
- 처음 빌드는 몇 분 걸린다. 창이 뜨면:
1. 로그인 화면의 계정 서버 주소가 `https://raspberry-pi.tailb6b7a3.ts.net:8443`인지 본다
2. `Google로 로그인` → 브라우저에서 **폰과 같은 구글 계정** 선택 → 앱으로 돌아온다
3. 시작하기 화면
   - [x] 버튼이 위에서부터 `이 계정의 다른 기기로 연결`, `새 그룹 만들기`, `코드로 참여`
4. 기기 이름을 `PC-A`로 바꾸고 `새 그룹 만들기`
   - [x] 홈 화면 맨 위 `연결됨`, 릴레이 주소 칸이 `wss://raspberry-pi.tailb6b7a3.ts.net`

### 2-2. 앱 B 띄우기 (창 B, 새 PowerShell)

```powershell
cd C:\Users\jonghyeok\Documents\clip-ferry
$env:CF_DESKTOP_PROFILE = "f37b"
$env:CF_RELAY = "wss://raspberry-pi.tailb6b7a3.ts.net"
$env:CF_ACCOUNT = "https://raspberry-pi.tailb6b7a3.ts.net:8443"
.\target\debug\clip-ferry-desktop.exe
```
- 이 exe는 앱 A의 개발 서버에서 화면을 받는다. **창 A를 켜 둔 동안에만** 화면이 뜬다.
1. `Google로 로그인` → **앱 A와 같은 구글 계정**
2. 시작하기 화면에서 기기 이름을 `PC-B`로 바꾸고 `이 계정의 다른 기기로 연결`
   - [x] `그룹에 참여하는 중` 화면, `같은 계정의 다른 기기에서 연결을 눌러 주기를 기다리는 중입니다…`

### 2-3. 연결

3. 앱 A
   - [x] 몇 초 안에 Windows 알림 `새 기기 'PC-B'이(가) 같은 계정으로 연결을 요청합니다…`
   - [x] 홈 화면 위쪽에 `새 기기 연결 요청` 카드: `… PC-B 기기가 이 그룹에 들어오려고 합니다`, 버튼 `연결`·`무시`
4. 앱 A에서 `연결`
   - [x] 앱 A: `참여 요청` 화면, `PC-B 기기가 이 그룹에 참여하려고 합니다`, 6자리 숫자
   - [x] 앱 B: `PC-A 기기 화면에 아래와 같은 숫자가…`, 6자리 숫자
   - [x] **두 숫자가 같다**
5. 앱 A에서 `같음, 승인`
   - [x] 앱 A: `기기를 추가했습니다` → `확인` → 기기 2대(PC-A, PC-B)
   - [x] 앱 B: 홈 화면, `연결됨`, 기기 2대
6. 앱 A의 기기 목록에서 PC-B, 앱 B의 목록에서 PC-A
   - [x] 둘 다 `온라인` (두 앱이 같은 PC 클립보드를 쓰므로 복사로는 구분하지 않는다)

### 2-4. 무시·거절

7. 앱 B 트레이 아이콘 오른쪽 클릭 → **종료**. 앱 A의 기기 목록에서 PC-B를 **제거**
8. 앱 B를 다시 켠다(창 B에서 `.\target\debug\clip-ferry-desktop.exe`. 같은 창이라 환경 변수는 남아 있다)
   - [ ] `다시 페어링 필요` 화면, `이 기기는 그룹에서 제거되었습니다.`
   - `다시 페어링` → `이 기기에서 그룹 정보 지우기` → 시작하기 화면 → `이 계정의 다른 기기로 연결`
9. 앱 A의 카드에서 `무시`
   - [ ] 카드가 사라진다. 앱 B는 계속 기다린다(10분 뒤 시간 초과)
10. 앱 B에서 `취소` → 다시 `이 계정의 다른 기기로 연결` → 앱 A 카드 `연결` → 숫자 화면에서 앱 A `거절`
   - [ ] 앱 B: `참여하지 못했습니다`, `초대한 기기가 거절했거나 초대가 만료되었습니다`
11. 앱 B는 트레이 → 종료하고 창 B는 닫는다. 앱 A도 트레이 → 종료(창 A의 `npm run tauri dev`도 끝난다. 안 끝나면 Ctrl+C)

## 3. 폰 = 기존 기기 (새 PC 앱 C가 폰의 진짜 그룹에 들어온다)

## 끝나면 (정리)

1. **설치된 PC 앱**에서 PC-C를 **제거**한다(기기 목록 → PC-C → 제거). 폰과 설치된 앱만 남는다
2. 앱 C: 트레이 → 종료. 창 A의 `npm run tauri dev`도 끝난다(안 끝나면 Ctrl+C)
3. 시험용 프로필 지우기(선택, PowerShell):
   ```powershell
   Remove-Item -Recurse "$env:APPDATA\app.clipferry.desktop\profiles\f37a", "$env:APPDATA\app.clipferry.desktop\profiles\f37b", "$env:APPDATA\app.clipferry.desktop\profiles\f37b2", "$env:APPDATA\app.clipferry.desktop\profiles\f37c"
   ```

   (Windows 자격 증명 관리자에 `clip-ferry-f37a`·`clip-ferry-f37b`·`clip-ferry-f37b2`·`clip-ferry-f37c` 항목이 남는다. 그대로 둬도 된다)
4. Pi는 PR이 머지되면 `git checkout main && git pull`로 되돌린다

## 막히면

| 보이는 것 | 원인 | 할 일 |
|---|---|---|
| 기존 기기에 요청 카드가 안 뜬다 | 두 기기의 구글 계정이 다르다 / 기존 기기가 `연결됨`이 아니다 / 기존 기기 앱이 예전 버전이다 | 두 기기의 계정 칸 이메일이 같은지, 기존 기기가 `연결됨`인지 본다. 기존 기기는 이 브랜치여야 한다(설치된 PC 앱은 응답하지 못한다) |
| 기존 기기가 방금 켜졌는데 카드가 안 뜬다 | 세션을 연 뒤 계정 서버에서 계정 정보를 받기 전이다 | 몇 초 기다린다. 새 기기는 3초마다 다시 요청한다 |
| 새 기기에서 `계정 서버가 계정 연결을 받지 않습니다 (예전 버전)` | Pi 계정 서버가 예전 코드 | 1절을 다시 |
| 새 기기에서 `계정 서버(…)에 연결하지 못했습니다` | 계정 서버 주소·Tailscale | 주소 확인, 폰 Tailscale 켜기 |
| 새 데스크톱 앱이 계속 기다림 | 릴레이 주소가 기존 기기와 다르다(`CF_RELAY` 없이 띄워서 `ws://127.0.0.1:8787`) | 그 앱을 트레이 → 종료. 이미 만든 프로필은 설정이 남고, 폴더만 지우면 키 저장소와 짝이 안 맞아 켜지지 않는다. **새 프로필 이름**(예: `f37b2`)과 `$env:CF_RELAY`·`$env:CF_ACCOUNT`를 같은 창에서 넣고 다시 띄운다 |
| 이미 그룹에 있는 기기가 요청하면 아무 일도 없다 | 정상(이미 구성원인 기기의 요청은 버린다) | 기존 기기에서 그 기기를 제거한 뒤 다시 |
| 숫자가 다르다 | 다른 기기가 끼어들었거나 버그 | **승인하지 말고** `거절`. 화면 사진과 함께 "시험 중 나온 것"에 적는다 |
| `installRelease`가 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`·`VERSION_DOWNGRADE` | 서명 키·버전 | **지우지 말고** 알려 준다. `CLIPFERRY_VERSION_CODE`를 더 크게(7 등) |

## 알려진 사항

- 기존 기기 앱은 이 브랜치(또는 이후) 버전이어야 요청에 응한다. 지금 설치된 PC 앱(예전 버전)은 요청을 보지 못한다.
- 요청은 10분 동안 유효하다(확인서 만료). 그동안 새 기기는 3초마다 다시 보낸다.
- 같은 계정의 기기가 여럿 켜져 있으면 모두에 카드가 뜬다. 먼저 `연결`을 누른 기기 하나만 이어진다. 나머지 카드는 `무시`하면 된다.
- 다른 계정의 요청이 보이지 않는 것, 계정 서버가 끼어들면 숫자가 달라지는 것은 자동 테스트(`other_account_request_is_not_shown`, `man_in_the_middle_with_secret_gets_different_sas`)로 확인했다.

## 먼저 알아둘 것

- 이번 범위: 계정 서버(`account/`, 크레이트 `clip-ferry-account`)만. 앱 로그인 화면(F34~F36)과 릴레이 토큰 확인(F33)은 아직 없다. 지금은 **계정 서버의 시험 페이지에서 실제 구글 로그인**을 해 본다.
- 하는 일: 구글 ID 토큰 검증(구글 공개키, `aud`·`iss`·만료·이메일 확인) → 계정 만들기/갱신 → 접속 토큰(1시간, Ed25519 JWT) + 갱신 토큰(30일, 쓸 때마다 교체, DB에는 해시만).
- 저장하는 것: 구글 `sub`·이메일·이름·사진 URL·가입/마지막 로그인 시각, 기기 목록, 갱신 토큰 해시. (사용량 표는 만들어 두었고 F33에서 채운다.)
- 이미 해 둔 것(Windows): `cargo test -p clip-ferry-account` 18개 통과(메모리 저장소). 가짜 "구글" 키로 위조·만료·다른 클라이언트·다른 발급자·이메일 미확인·HS256 위조를 모두 거부, 갱신 토큰 재사용 시 그 계정의 모든 갱신 토큰 무효화, DB에 원문 없음. fmt·clippy 경고 없음.
- **MariaDB로는 아직 돌려 보지 않았다**(이 PC의 Docker가 꺼져 있음). PR CI의 `account (MariaDB)` 작업이 실제 MariaDB 11.4로 같은 시험을 돌린다. 이것이 처음 확인이다.

## 2. Pi에 MariaDB와 함께 (선택, F33 전에 하면 좋다)

Pi 주소: `raspberry-pi.tailb6b7a3.ts.net`. 계정 서버는 **`https://raspberry-pi.tailb6b7a3.ts.net:8443`**(릴레이는 같은 이름의 443). 명령은 모두 **Pi 터미널(SSH)**에서 친다.

**① 이번 코드 받기**
```bash
cd ~/clip-ferry          # 릴레이를 올릴 때 받아 둔 저장소 폴더
git fetch && git checkout f32-account && git pull
```

**② 설정 파일 만들기** (통째로 한 번에 붙여넣기. DB 암호·서명 키는 무작위로 만들어진다)
```bash
cat > deploy/.env.account <<EOF
CF_DB_PASSWORD=$(openssl rand -hex 24)
CF_ACCOUNT_SIGNING_KEY=$(openssl rand 32 | base64 | tr '+/' '-_' | tr -d '=')
CF_GOOGLE_CLIENT_IDS=459283262663-4raksn21of8l1ltsd9t413fa3oav4sak.apps.googleusercontent.com
CF_DEV_PAGES=true
EOF
chmod 600 deploy/.env.account
```

**③ 계정 서버 + DB 띄우기** (처음엔 빌드로 10~20분)
```bash
docker compose --env-file deploy/.env.account -f deploy/compose.account.yml up -d --build
docker compose --env-file deploy/.env.account -f deploy/compose.account.yml logs account
```
- [x] 로그에 `listening on 0.0.0.0:8788`

**④ 밖에서 접속되게 열기**

## 시험 중 나온 것

- 2026-11-06: 시험 페이지에서 로그인하면 404. 페이지(`/dev/google`)가 API를 상대 경로(`v1/…`)로 불러 `/dev/v1/…`로 갔다 → 절대 경로(`/v1/…`)로 고침, 테스트에 경로 확인 추가
- 2026-11-06 (Pi): 로그인 500. 로그 `mismatched types; Rust type String … not compatible with SQL type BINARY`. 0001의 정렬 규칙 `utf8mb4_bin` 때문에 MariaDB가 문자열 칸을 BINARY로 알렸다 → 마이그레이션 `0002_collation.sql`(외래 키를 잠시 지우고 `utf8mb4_unicode_ci`로 바꾼 뒤 다시 만듦. FK 검사를 꺼도 참조되는 칸은 못 바꿔 오류 1833). 새 마이그레이션 파일이 다시 컴파일되지 않던 것도 `build.rs`로 고침. 이 PC의 MariaDB 11.4 컨테이너로 두 경우 확인: 0001만 적용된 DB(Pi와 같음)에서 올리기, 빈 DB(CI와 같음) — 둘 다 18개 통과
- 클라이언트 보안 비밀(client secret)은 쓰지 않는다. 이 문서·저장소에 적지 않는다

## 알려진 사항

- 같은 갱신 토큰을 두 번 보내면(앱이 재시도 등) 재사용으로 보고 그 계정의 모든 로그인을 끊는다. 앱(F34~)은 갱신을 한 번에 하나씩 해야 한다.
- 계정 삭제(`DELETE /v1/me`)는 F39에서 한다.
- 개발용 CLI 로그인(`cf login --dev`)은 릴레이가 토큰을 요구하게 되는 F33에서 붙인다. 계정 서버 쪽 `POST /v1/auth/dev`(`--dev-login`)는 이미 있다.

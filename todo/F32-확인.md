# F32. 계정 서버 + 구글 로그인 검증 — 확인할 것

상태: `진행중` (docs/05-progress.md). 브랜치 `f32-account` (`m7-accounts-docs` 위).

## 먼저 알아둘 것

- 이번 범위: 계정 서버(`account/`, 크레이트 `clip-ferry-account`)만. 앱 로그인 화면(F34~F36)과 릴레이 토큰 확인(F33)은 아직 없다. 지금은 **계정 서버의 시험 페이지에서 실제 구글 로그인**을 해 본다.
- 하는 일: 구글 ID 토큰 검증(구글 공개키, `aud`·`iss`·만료·이메일 확인) → 계정 만들기/갱신 → 접속 토큰(1시간, Ed25519 JWT) + 갱신 토큰(30일, 쓸 때마다 교체, DB에는 해시만).
- 저장하는 것: 구글 `sub`·이메일·이름·사진 URL·가입/마지막 로그인 시각, 기기 목록, 갱신 토큰 해시. (사용량 표는 만들어 두었고 F33에서 채운다.)
- 이미 해 둔 것(Windows): `cargo test -p clip-ferry-account` 18개 통과(메모리 저장소). 가짜 "구글" 키로 위조·만료·다른 클라이언트·다른 발급자·이메일 미확인·HS256 위조를 모두 거부, 갱신 토큰 재사용 시 그 계정의 모든 갱신 토큰 무효화, DB에 원문 없음. fmt·clippy 경고 없음.
- **MariaDB로는 아직 돌려 보지 않았다**(이 PC의 Docker가 꺼져 있음). PR CI의 `account (MariaDB)` 작업이 실제 MariaDB 11.4로 같은 시험을 돌린다. 이것이 처음 확인이다.

## 1. PC에서 빠르게 (DB 없이, 메모리)

PowerShell, 저장소 폴더에서:

```powershell
$env:CF_ACCOUNT_SIGNING_KEY = (cargo run -q -p clip-ferry-account -- gen-key)
cargo run -q -p clip-ferry-account -- --memory-store --dev-pages --google-client-ids <클라이언트 ID>
```

- [ ] 로그에 `memory store` 경고와 `listening on 127.0.0.1:8788`
- [ ] 브라우저로 **`http://localhost:8788/dev/google`** (127.0.0.1이 아니라 localhost) → `Google 계정으로 로그인` 버튼
- [ ] 로그인 → `로그인 성공`, 아래에 내 이메일·이름, `access_token`·`refresh_token`은 `(받음)`
- [ ] `내 계정 보기` → 200, `devices: []`
- [ ] `시험 기기 등록` → 200 → 다시 `내 계정 보기`에 기기 1개
- [ ] `토큰 갱신` → `갱신 성공`. 한 번 더 `토큰 갱신`도 성공(매번 새 토큰)
- [ ] `로그아웃` → 204 → `토큰 갱신` 버튼이 꺼진다
- [ ] 테스트 사용자로 넣지 않은 다른 구글 계정으로 로그인하면 구글 화면에서 막힌다(정상)
- 끄기: 터미널에서 Ctrl+C. 메모리라 계정이 사라진다.

## 2. Pi에 MariaDB와 함께 (선택, F33 전에 하면 좋다)

`deploy/README.md` "계정 서버" 2~3절. Pi에서 이 브랜치를 받는다: `git fetch && git checkout f32-account`.

- [ ] `docker compose … up -d --build` 뒤 `logs account`에 `listening on 0.0.0.0:8788`
- [ ] `tailscale serve --https=8443` 뒤 PC에서 `https://<Pi>.ts.net:8443/healthz` → `ok`
- [ ] `https://<Pi>.ts.net:8443/dev/google`에서 1절의 로그인·내 계정·기기 등록·갱신·로그아웃이 같은 결과
- [ ] `docker compose … restart` (또는 Pi 재부팅) 뒤 다시 로그인하면 **같은 계정 ID**, `내 계정 보기`에 아까 등록한 기기가 남아 있다
- [ ] 다 보면 `.env.account`에서 `CF_DEV_PAGES=false`로 바꾸고 다시 `up -d`

## 알려진 사항

- 같은 갱신 토큰을 두 번 보내면(앱이 재시도 등) 재사용으로 보고 그 계정의 모든 로그인을 끊는다. 앱(F34~)은 갱신을 한 번에 하나씩 해야 한다.
- 계정 삭제(`DELETE /v1/me`)는 F39에서 한다.
- 개발용 CLI 로그인(`cf login --dev`)은 릴레이가 토큰을 요구하게 되는 F33에서 붙인다. 계정 서버 쪽 `POST /v1/auth/dev`(`--dev-login`)는 이미 있다.

## 먼저 알아둘 것 (결정 필요 아님, 확인만)

- 텍스트 최대가 1 MiB인데 릴레이 프레임 한도가 512 KiB라서 한 봉투에 들어가지 않았다. **프레임 한도를 2 MiB로 올렸다**(D-012). 마음에 안 들면 알려 달라 — 텍스트를 청크로 쪼개는 방식으로 바꿀 수 있다.
- 3개 프로필이 서로 보내려면 새로 들어온 기기를 기존 기기가 알아야 해서, F08에 있던 **`RosterUpdate` 채택을 일부 앞당겨 구현**했다(기기 제거·키 회전은 F08 그대로).

## 직접 확인할 것 (PowerShell, 터미널 4개)

사전 준비: `a`, `b` 프로필이 같은 그룹이어야 한다. F06 때 만든 프로필이 남아 있으면 그대로 쓰면 되고, 없으면 `.cf-profiles` 폴더를 지우고 F06 순서대로 `a`(init, group create), `b`(init, invite/join)를 다시 만든다.

- 터미널 1: `cargo run -p clip-ferry-relay -- --listen 127.0.0.1:8787`
- 터미널 B: `cargo run -q -p clip-ferry-cli -- --profile b listen`
- 터미널 A: `cargo run -q -p clip-ferry-cli -- --profile a send "안녕 clip-ferry"`

- [x] B에 `[laptop] 안녕 clip-ferry` (laptop은 a 프로필을 init할 때 정한 이름), A에 `delivered=1`
- [x] 터미널 1(릴레이)에는 내용이 없고 시작 메시지만 있음 (60초마다 숫자 집계 한 줄)
- [x] (선택) `"줄1`nline2" | cargo run -q -p clip-ferry-cli -- --profile a send` 처럼 표준 입력으로 보내도 B에 도착
- [x] (선택) B를 Ctrl+C로 끈 뒤 A에서 보내면 `delivered=0`. B를 다시 켜면 그 사이 메시지는 오지 않음(릴레이는 저장하지 않는다)
- [x] (선택) 릴레이를 껐다 켜면 B에 `reconnecting...` 뒤 `connected`, 이후 보낸 것은 다시 도착

## 참고

- `send`는 텍스트를 생략하거나 `-`를 주면 표준 입력을 읽고, 끝의 줄바꿈 하나는 지운다.
- 받은 내용을 터미널에 찍을 때 제어 문자(화면 조작용 이스케이프 등)는 `?`로 바꾼다. 줄바꿈과 탭은 그대로.
- 빈 텍스트는 보내지 않는다.
- 푸시·앱이 꺼진 기기 처리는 아직 없다. 꺼져 있는 동안의 메시지는 받지 못한다(무저장 설계).

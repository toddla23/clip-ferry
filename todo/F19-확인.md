# F19. Android 공유 메뉴 · 텍스트 선택 메뉴 — 확인할 것

상태: `진행중` (docs/05-progress.md). 브랜치 `f19-android-share`. 7번(직접 공유 바로가기)을 더해 그 부분만 다시 확인한다.

**확인 결과 (2026-11-05, 사용자 보고)**: 1~6번 모두 통과. 갤러리 공유(한 장·여러 장·HEIC), 텍스트 선택 메뉴(원래 글 그대로), 텍스트 공유, 중지 상태에서 자동 연결 후 전송, 받을 기기 없음 안내, 동영상·PDF 제외, 화면 회전 시 한 번만 전송. 텍스트 선택 메뉴 이름은 별칭 액티비티로 고친 뒤 통과.

## 먼저 알아둘 것

- 이번 범위: 복사하지 않고 **공유 시트나 텍스트 선택 메뉴에서 바로** 다른 기기로 보낸다.
  - 공유 시트의 `다른 기기로 보내기` (clip-ferry 아이콘): 텍스트, 이미지 한 장, 이미지 여러 장
  - 텍스트를 길게 눌러 나오는 선택 메뉴의 `PC로 보내기` (메뉴가 짧으면 ⋮ 안에 있다)
- 화면은 뜨지 않는다. 결과는 F18과 같은 토스트로 알린다.
  - 예: `텍스트를 다른 기기 1대로 보냈습니다`, `이미지 3장을 다른 기기 1대로 보냈습니다`, `3장 중 2장만 보냈습니다 (…)`
- 여러 장은 **한 장씩 차례로** 보낸다. PC 클립보드에는 **마지막 장**이 남는다(알려진 동작).
- 공유로 받은 이미지는 읽을 권한이 잠깐만 있으므로, 먼저 앱 캐시(`cache/outgoing/`)에 복사해 두고 보낸 뒤 지운다.
  - 이미지가 크거나 많으면 복사하는 동안(1~2초) 손을 대도 반응이 없을 수 있다.
- 사용자가 직접 고른 내용이므로 `민감한 내용도 보내기` 설정은 따지지 않는다.
- 형식·크기 규칙은 F18과 같다: PNG·JPEG·GIF·WebP는 그대로, HEIC 등은 JPEG로. 한 장 20 MiB까지.
- 연결이 꺼져 있으면 F18처럼 연결을 켜고 최대 8초 기다린 뒤 보낸다.
- 이미 해 둔 것(Windows): `assembleDebug` 성공(경고 없음). 코어·FFI는 바꾸지 않았다(F18의 `send_text`·`send_image`를 그대로 쓴다).

## 7. 직접 공유 바로가기 (추가)

공유 시트 맨 윗줄(연락처·대화방이 뜨는 줄)에 `다른 기기로`(clip-ferry 아이콘) 바로가기를 띄운다. 탭 수는 같지만 찾거나 스크롤할 필요가 없다.

1. 새로 설치했으면 clip-ferry 앱을 한 번 연다(앱이 켜질 때 바로가기를 등록한다).
2. 모바일 Chrome에서 이미지를 꾹 눌러 `이미지 공유`, 또는 갤러리에서 `공유`.

- [ ] 공유 시트 맨 윗줄(또는 앞쪽)에 `다른 기기로` 바로가기가 보인다
  - 처음엔 안 보이거나 늦게 뜰 수 있다. 일반 목록의 `다른 기기로 보내기`를 몇 번 쓰면 시스템이 앞으로 올린다

## 시험 중 나온 것

- 2026-11-05: 텍스트 선택 메뉴에 `PC로 보내기`가 아니라 `clip-ferry`로 보였다(전송은 정상). intent-filter 이름 대신 액티비티 이름을 쓰는 것으로 보여, `PROCESS_TEXT`를 이름 `PC로 보내기`인 별칭 액티비티(`ProcessTextAlias`)로 옮겼다. 공유 시트 쪽은 액티비티 이름을 `다른 기기로 보내기`로 지정했다. 다시 설치 후 4번 통과.

## 알려진 사항 (이번 범위 밖)

- 릴레이는 연결당 분당 64 MiB까지만 받는다. 큰 사진을 한 번에 많이(대략 합계 60 MiB 넘게) 보내면 뒤쪽 장이 속도 제한으로 실패해 `N장 중 M장만 보냈습니다`가 나올 수 있다. 실제로 나오면 알려 달라(코어에서 기다렸다 다시 보내도록 고칠 수 있다).
- 텍스트 선택 메뉴 이름은 사양대로 `PC로 보내기`다(삼성 One UI는 intent-filter 이름을 무시해 처음엔 `clip-ferry`로 보였다. 별칭 액티비티로 고침). 받는 쪽은 PC만이 아니라 그룹의 다른 기기 전부다. 공유 시트 이름은 `다른 기기로 보내기`.
- 받을 기기를 골라 보내기는 F30.

# F08. 기기 관리 · 키 회전 · 복구 — 확인할 것

상태: `확인대기` (docs/05-progress.md)

## 먼저 알아둘 것

- **한 기기는 한 프로세스**여야 한다. 같은 `--profile`을 두 터미널에서 동시에 `listen`과 `remove`로 돌리면, 한쪽이 키를 바꿔도 다른 쪽은 메모리에 옛 상태를 들고 있어 따라가지 못한다(실제 앱은 기기당 하나만 돈다).
- 03-protocol의 "질의에 응답"만으로는 `remove` 같은 한 번 실행하고 끝나는 명령 뒤에 꺼진 기기가 따라잡을 수 없다. 그래서 **이전 채널에 기다리고 있는 기기가 보이면 먼저 최신 키를 밀어 주는** 경로를 더했다(03-protocol 3.3에 적음).
- 동시에 서로 다른 기기를 제거하면 그룹이 갈라질 수 있다(알려진 한계, 03-protocol 3.2).

## 직접 확인할 것 (PowerShell, 터미널 여러 개)

사전 준비: 깨끗한 상태가 좋다. 이전에 만든 `.cf-profiles` 폴더는 지우고(`Remove-Item -Recurse .cf-profiles`), 릴레이를 새로 띄운다.

1. 터미널 1: `cargo run -p clip-ferry-relay -- --listen 127.0.0.1:8787`
2. a, b, c를 한 그룹으로 만든다 (F06 절차를 두 번). `cf`는 `cargo run -q -p clip-ferry-cli --` 로 대신해도 된다.

```
cf --profile a init --name laptop
cf --profile a group create
cf --profile b init --name phone-sim
cf --profile a invite          # 다른 터미널에서  cf --profile b join <코드>  후 a에서 y
cf --profile c init --name tablet
cf --profile a invite          # 다른 터미널에서  cf --profile c join <코드>  후 a에서 y
cf --profile a devices         # 3대, 에포크 1
```

3. **c의 `listen`은 켜지 않은 채** a에서 b를 제거한다:

```
cf --profile a remove phone-sim
```

   → `제거했습니다: phone-sim · 새 에포크 2 · 구성원 2명`

4. 터미널 B: `cf --profile b listen`, 터미널 C: `cf --profile c listen` 을 켠다.
5. 터미널 A: `cf --profile a send "after remove"`

- [x] C에 `키가 회전되었습니다 (에포크 2)` 뒤 `[laptop] after remove`가 찍힌다 (재접속 직후 따라잡기)
- [x] B에는 `removed or stale: 그룹에서 제거되었거나 …` 가 뜨고 프로그램이 끝난다. `after remove`는 오지 않는다
- [x] `cf --profile a devices` → `기기 2대 · 에포크 2`, `cf --profile c devices` 도 같음
- [x] `cf --profile b status` 의 `상태:` 가 `removed or stale (그룹에서 제거됨)`
- [x] (선택) `cf --profile b send "x"` → `Error: removed or stale: …` 로 거부됨
- [x] (선택) `cf --profile c rename tablet-2` 후 `cf --profile a devices` 에 `tablet-2`가 보임 (a가 그때 실행 중이 아니면 안 바뀐다 — 로스터 변경은 온라인인 기기만 받는다)

## 참고

- 제거할 기기는 이름 또는 device_id 앞자리(hex 4자 이상)로 지정한다. 이름이 겹치면 id 앞자리를 쓴다.
- 제거된 기기의 `listen`/`send`는 시작하지 못하거나(이미 제거를 알면) 제거를 알게 되는 즉시 끝난다. 다시 쓰려면 새 프로필로 페어링한다.
- 이름 변경(`rename`)은 온라인인 기기만 받는다. 꺼져 있던 기기는 다음에 다른 변경이나 키 회전을 받을 때 따라잡는다(로스터 전체 동기화는 이후 과제).

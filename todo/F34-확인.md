# F34. 데스크톱 로그인 — 확인할 것

상태: `진행중` (docs/05-progress.md). 브랜치 `f34-desktop-login`.

이 문서만 보고 처음부터 끝까지 따라 할 수 있게 썼다. 각 단계는 **할 일 → 보여야 하는 것** 순서다. 다르게 보이면 맨 아래 "막히면"을 먼저 보고, 그래도 안 되면 그 화면·로그를 "시험 중 나온 것"에 적는다.

## 무엇을 시험하나

- 데스크톱 앱이 **구글 로그인을 한 뒤에만** 릴레이에 연결한다. 로그인 전에는 로그인 화면만 보인다.
- 로그인: 앱의 `Google로 로그인` → 기본 브라우저에서 구글 계정 선택 → 앱으로 돌아온다.
- 앱을 다시 켜도 로그인이 유지된다. 갱신 토큰은 Windows 자격 증명 관리자에, 1시간짜리 접속 토큰은 메모리에만 둔다.
- 로그아웃하면 연결을 끊고 자격 증명 관리자의 로그인 정보를 지운다. **그룹·페어링은 남는다**. 다시 로그인하면 바로 이어서 쓴다.
- 구글과 코드를 바꾸는 일은 계정 서버가 한다(D-020). 그래서 구글 콘솔에 **"데스크톱 앱" 클라이언트**가 하나 더 필요하다. 그 보안 비밀은 **계정 서버에만** 준다.

## 시험 구성 (전부 이 PC 안에서)

```
창 1  계정 서버   http://127.0.0.1:8788   (메모리 저장, 끄면 계정이 사라짐)
창 2  릴레이      ws://127.0.0.1:8787     (접속 토큰을 확인함)
창 3  앱 A        프로필 f34a             (npm run tauri dev, 구글 로그인으로 시험)
창 4  앱 B        프로필 f34b             (빌드된 exe 직접 실행, 개발용 로그인)
브라우저          구글 로그인 화면
```

- **프로필**: `CF_DESKTOP_PROFILE`을 주면 데이터 폴더와 자격 증명 이름이 따로 생긴다. 지금 쓰는 앱 데이터와 Pi·폰 동기화는 1~6절에서 건드리지 않는다.
- **앱 B를 `npm run tauri dev`로 띄우지 않는 이유**: 화면 개발 서버가 포트 1420 하나만 쓴다. 두 번째 `npm run tauri dev`는 `Port 1420 is already in use`로 실패한다. 그래서 앱 B는 앱 A가 빌드해 둔 exe를 직접 실행한다. 이 exe는 앱 A의 개발 서버에서 화면을 받으므로 **앱 A(창 3)를 켜 둔 동안에만** 화면이 뜬다.
- **설치해 둔 clip-ferry**(트레이에 있는 것)는 1~6절 동안 켜 둬도 된다. 다만 복사한 내용이 폰으로도 간다. 헷갈리면 트레이 → 종료. **7절 전에는 반드시 종료한다**(같은 데이터를 쓴다).

## 0. 구글 콘솔: 데스크톱 클라이언트 만들기 (한 번만)

F32 때 만든 프로젝트(`clip-ferry`)와 OAuth 동의 화면을 그대로 쓴다.

1. 브라우저에서 https://console.cloud.google.com/ → 위쪽 프로젝트 선택에서 `clip-ferry` 프로젝트인지 확인
2. 왼쪽 메뉴 **API 및 서비스 → 사용자 인증 정보**(또는 Google Auth Platform → **클라이언트**)
3. **+ 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
4. 애플리케이션 유형 **데스크톱 앱**, 이름 `clip-ferry desktop` → **만들기**
   - 리디렉션 URI 칸은 없다. 구글이 `http://127.0.0.1:<포트>`를 알아서 받는다.
5. 팝업에 나온 두 값을 메모장에 잠깐 적어 둔다(팝업을 닫아도 클라이언트 목록에서 다시 볼 수 있다).
   - **클라이언트 ID**: `…apps.googleusercontent.com`으로 끝난다.
   - **클라이언트 보안 비밀**: `GOCSPX-`로 시작한다. 이 값은 채팅·이 문서·git에 적지 않는다.
6. **OAuth 동의 화면 → 대상(테스트 사용자)**에 로그인할 구글 계정이 있는지 본다. 없으면 **+ Add users**로 넣는다. 게시 상태는 **테스트** 그대로 둔다.

- [x] 클라이언트 목록에 유형 "데스크톱"인 `clip-ferry desktop`이 있다
- [x] 테스트 사용자에 내 구글 계정이 있다

## 준비 B. 창 1 — 계정 서버

새 PowerShell 창을 열고 아래를 **한 줄씩** 친다. `<…>` 두 곳에는 0절에서 적은 값을 넣는다. 따옴표는 남긴다.

```powershell
cd C:\Users\jonghyeok\Documents\clip-ferry
$env:CF_ACCOUNT_SIGNING_KEY = (cargo run -q -p clip-ferry-account -- gen-key)
$env:CF_ACCOUNT_GOOGLE_DESKTOP_CLIENT_ID = "<클라이언트 ID>"
$env:CF_ACCOUNT_GOOGLE_DESKTOP_CLIENT_SECRET = "<클라이언트 보안 비밀>"
cargo run -q -p clip-ferry-account -- --memory-store --dev-login --usage-secret test123
```

보여야 하는 것:
- [x] `memory store: data is lost on restart (development only)`, `dev login enabled: …` 경고 두 줄. 정상이다.
- [x] `listening on 127.0.0.1:8788 (signing key …)`
- [x] `no google desktop client; desktop login is disabled` 경고가 **없다**. 있으면 위 두 `$env:` 줄을 빠뜨렸거나 다른 창에서 친 것이다.

이 창은 끝날 때까지 켜 둔다. 끄면(Ctrl+C) 계정이 모두 사라진다. 다시 켤 때는 마지막 `cargo run` 줄만 다시 치면 된다(같은 창이면 `$env:` 값이 남아 있다).

## 준비 C. 창 2 — 릴레이 (접속 토큰 확인 켬)

- 1분마다 `connections=… open=… rejected=… unauthorized=… …` 줄이 찍힌다. 아래 단계에서 이 줄을 본다.

## 알려진 사항

- 로그인하려면 계정 서버가 구글(`oauth2.googleapis.com`)에 닿아야 한다. 로그인 뒤 갱신에는 계정 서버만 있으면 된다.
- 계정 서버에 닿지 않는 동안에는 접속 토큰을 갱신하지 못한다. 그래서 토큰을 확인하는 릴레이에는 연결되지 않는다. 로그아웃되지는 않고, 다시 닿으면 연결된다.
- 같은 프로필로 앱을 두 개 띄우면 갱신 토큰이 꼬여(재사용 감지) 둘 다 로그아웃될 수 있다. 프로필마다 하나만 띄운다.
- Apple 로그인은 F41.

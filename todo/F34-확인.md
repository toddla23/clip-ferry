# F34. 데스크톱 로그인 — 확인할 것

상태: `진행중` (docs/05-progress.md). 브랜치 `f34-desktop-login`.

## 먼저 알아둘 것

- 이번 범위: 데스크톱 앱이 **구글 로그인 뒤에만** 릴레이에 연결한다. 첫 화면에 `Google로 로그인` → 시스템 브라우저에서 구글 로그인 → 앱으로 돌아온다. 갱신 토큰은 Windows 자격 증명 관리자(keyring)에, 접속 토큰(1시간)은 메모리에만 둔다.
- 기존 사용자: 업데이트해도 **그룹·페어링은 그대로**이고 로그인만 하면 이어서 쓴다. 로그아웃해도 그룹은 남는다.
- 구글과의 코드 교환은 계정 서버가 한다(D-020). 그래서 구글 콘솔에 **"데스크톱 앱" 클라이언트**를 하나 더 만들고, 그 ID·보안 비밀을 **계정 서버에만** 준다.
- 계정 서버 주소는 앱의 로그인 화면 `서버 설정`에서 바꾼다(기본 `http://127.0.0.1:8788`). 로그인한 뒤에는 로그아웃해야 바꿀 수 있다.
- 개발 빌드(`npm run tauri dev`)의 로그인 화면 아래에는 **개발용 로그인**(이메일만, 계정 서버 `--dev-login`) 칸이 있다. 배포 빌드에는 없다.
- 이미 해 둔 것(Windows): 계정 서버 테스트(가짜 구글 토큰 주소로 코드 교환 성공·틀린 코드·루프백이 아닌 주소 거부·다른 클라이언트용 토큰 거부·구글 장애), 데스크톱 테스트(PKCE RFC 예시, 루프백이 틀린 `state` 무시, 실제 계정 서버로 로그인·동시 갱신·재시작·로그아웃·거절된 갱신 토큰 삭제).

## 0. 구글 콘솔: 데스크톱 클라이언트 (한 번만)

`deploy/README.md` "계정 서버" 1절 5번.

- [ ] 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID → 유형 **데스크톱 앱** → 만들기
- [ ] 클라이언트 ID와 클라이언트 보안 비밀을 적어 둔다(보안 비밀은 이 문서·채팅·git에 적지 않는다)

## 준비 (PowerShell 창 3개, 모두 저장소 폴더에서)

**창 1 — 계정 서버** (메모리, 개발용 로그인도 켬, 사용량 비밀 `test123`)
```powershell
$env:CF_ACCOUNT_SIGNING_KEY = (cargo run -q -p clip-ferry-account -- gen-key)
$env:CF_ACCOUNT_GOOGLE_DESKTOP_CLIENT_ID = "<0의 클라이언트 ID>"
$env:CF_ACCOUNT_GOOGLE_DESKTOP_CLIENT_SECRET = "<0의 보안 비밀>"
cargo run -q -p clip-ferry-account -- --memory-store --dev-login --usage-secret test123
```
- [ ] `listening on 127.0.0.1:8788`, `no google desktop client` 경고가 **없다**

**창 2 — 릴레이** (토큰 확인 켬)
```powershell
cargo run -q -p clip-ferry-relay -- --account-url http://127.0.0.1:8788 --usage-secret test123
```
- [ ] `access tokens required (account server set)`

**창 3 — 앱 A** (시험용 프로필 `f34a`, 지금 쓰는 앱 데이터는 건드리지 않는다)
```powershell
cd apps/desktop
$env:CF_DESKTOP_PROFILE = "f34a"
$env:CF_RELAY = "ws://127.0.0.1:8787"
npm run tauri dev
```

## 1. 로그인 전에는 연결하지 않는다

- [ ] 창에 `clip-ferry 로그인`과 `Google로 로그인` 버튼만 있다. 트레이 아이콘에 마우스를 올리면 `clip-ferry — 로그인 필요`
- [ ] 창 2(릴레이) 로그의 1분 집계에 `unauthorized=0`이고 연결이 늘지 않는다(앱이 아예 연결하지 않음)

## 2. 구글 로그인

- [ ] `Google로 로그인` → 기본 브라우저에 구글 계정 선택 화면이 열리고, 앱에는 `브라우저에서 구글 로그인을 마치세요…`
- [ ] 테스트 사용자 계정으로 로그인 → (처음이면 "확인되지 않은 앱" 안내 → 계속) → 브라우저에 `로그인했습니다. 이 창을 닫고 clip-ferry로 돌아가세요.`
- [ ] 앱이 `clip-ferry 시작하기`(새 그룹 / 코드로 참여)로 넘어간다
- [ ] `새 그룹 만들기` → `연결됨`. 설정 위 `계정`에 내 이름·이메일

## 3. 다시 켜도 로그인 유지

- [ ] 트레이 → 종료, 창 3에서 `npm run tauri dev` 다시 → 로그인 화면 없이 `연결됨`

- [ ] 앱 A `기기 추가` → 코드 복사 → 앱 B `코드로 참여`에 붙여넣기 → 양쪽 같은 숫자 → A에서 승인 → 둘 다 `연결됨`, 기기 2대

## 5. 로그아웃

- [ ] 앱 A `로그아웃` → 로그인 화면으로 돌아감, 트레이 `로그인 필요`. 앱 B의 기기 목록에서 A가 오프라인이 된다
- [ ] 자격 증명 관리자에서 로그인 정보가 지워졌다:
  ```powershell
  cmdkey /list | Select-String "account/session"
  ```
  → `clip-ferry-f34b`(앱 B)의 것만 남고 `clip-ferry-f34a`는 없다
- [ ] 앱 A로 다시 `Google로 로그인` → **새 그룹 화면이 아니라 바로 `연결됨`**, 기기 2대 그대로(그룹 유지)

## 6. 취소·거부

- [ ] 앱 A 로그아웃 → `Google로 로그인` → 앱에서 `취소` → 다시 `Google로 로그인` 버튼
- [ ] `Google로 로그인` → 구글 화면에서 창을 닫지 않고 **취소**(또는 계정 선택 뒤 "취소") → 앱에 `로그인을 취소했습니다`
- [ ] 계정 서버(창 1)를 Ctrl+C로 끄고 `Google로 로그인` → `계정 서버(…)에 연결하지 못했습니다`. 다시 켠다(메모리라 계정이 사라지므로 앱 A·B 모두 다시 로그인해야 한다 — 이때 앱이 `로그인이 만료되었습니다`로 로그인 화면에 돌아가면 정상)

## 7. 지금 쓰는 앱(기존 사용자) — 선택, Pi 계정 서버 필요

지금 쓰는 앱 데이터(프로필 없음)로 그룹이 그대로인지 본다. Pi 릴레이는 아직 토큰을 확인하지 않으므로 폰과의 동기화는 지금처럼 된다.

**Pi에서** (SSH):
```bash
cd ~/clip-ferry && git fetch && git checkout f34-desktop-login && git pull
nano deploy/.env.account     # 아래 두 줄 추가
#   CF_GOOGLE_DESKTOP_CLIENT_ID=<0의 클라이언트 ID>
#   CF_GOOGLE_DESKTOP_CLIENT_SECRET=<0의 보안 비밀>
docker compose --env-file deploy/.env.account -f deploy/compose.account.yml up -d --build
docker compose --env-file deploy/.env.account -f deploy/compose.account.yml logs account | grep -i desktop   # 경고가 없어야 한다
```

## 알려진 사항

- 로그인하려면 계정 서버가 구글(`oauth2.googleapis.com`)에 닿아야 한다. 로그인 뒤 갱신은 계정 서버만 있으면 된다.
- 계정 서버에 닿지 않는 동안에는 접속 토큰을 갱신하지 못해 토큰을 확인하는 릴레이에는 연결되지 않는다(로그아웃되지는 않고, 닿으면 다시 연결된다).
- 앱을 두 개 띄워 같은 프로필을 쓰면 갱신 토큰이 꼬여(재사용) 둘 다 로그아웃될 수 있다. 프로필마다 하나만 띄운다.
- Apple 로그인은 F41.

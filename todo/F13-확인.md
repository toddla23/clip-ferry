# F13. 기기 관리 UI와 설정 (데스크톱) — 확인할 것

상태: `완료` (macOS 실행은 미확인) (docs/05-progress.md)

## 먼저 알아둘 것

- **기기 목록**: 이름, 이 기기 표시, 짧은 id, **온라인 점**(초록=지금 그룹 채널에 붙어 있음). 온라인은 릴레이 Presence의 태그를 기기별 태그와 대조해 알아낸다. 이 기기는 릴레이에 연결돼 있으면 항상 온라인이다. 연결이 끊기면 다른 기기는 모두 오프라인으로 표시한다.
- **이름 변경은 이 기기만** 가능하다(다른 기기 이름은 그 기기에서 바꾼다). 바꾸면 그룹의 다른 기기 목록에도 반영된다.
- **제거**는 다른 기기만 가능하고 확인 단계가 있다(`제거` → `…을(를) 제거할까요?` → `제거`). 제거하면 키가 회전되어(에포크 +1) 제거된 기기는 이후 메시지를 읽을 수 없다.
- **플랫폼 표시는 이번에 넣지 않았다.** 로스터에 플랫폼 정보가 없어서 프로토콜을 바꿔야 한다(모바일 F15 이후에 같이 정하는 편이 낫다). 필요하면 알려 달라.
- **설정**
  - `복사한 내용을 다른 기기로 보내기` / `다른 기기에서 받은 내용을 클립보드에 쓰기`: 각각 켜고 끈다. `settings.json`에 저장되어 재시작해도 유지된다. 보내기가 꺼져 있으면 복사한 내용을 **읽지도 않는다.**
  - `일시정지`: 보내기·받기를 둘 다 멈춘다. 창의 버튼과 **트레이 메뉴의 `일시정지`/`재개`**가 같은 상태를 쓴다. 저장하지 않으므로 **앱을 다시 켜면 풀린다.** 일시정지 중에 복사한 내용은 재개한 뒤에도 보내지 않는다(재개한 뒤 새로 복사한 것부터 간다). 트레이 아이콘은 회색, 툴팁은 "일시정지".
  - `로그인할 때 자동으로 시작`: Windows는 시작 프로그램 레지스트리, macOS는 LaunchAgent로 등록한다. 개발 모드(`tauri dev`)로 켠 앱에서 켜면 **개발용 실행 파일 경로가 등록**되므로, 시험 뒤에는 다시 꺼 둔다.
  - 릴레이 주소: 기존과 같다.
- **다시 페어링 필요 화면**: 이 기기가 제거되었거나 30일 넘게 연락이 없으면(구성원이 둘 이상일 때) 기기 목록 대신 이 화면이 뜬다. `다시 페어링` → `이 기기에서 그룹 정보 지우기`를 누르면 **그룹 키와 목록을 지우고** 첫 마법사로 돌아간다(기기 이름·기기 키는 그대로). 거기서 새 그룹을 만들거나 초대 코드로 다시 참여한다. 트레이 아이콘은 빨강, 툴팁은 "다시 페어링 필요".
- 코어에 `leave_group()`(그룹에서 나가기)과 `Session`의 `on_presence`를 추가했다.

## 직접 확인할 것 (PowerShell)

준비는 `todo/F12-확인.md`의 "준비"와 같다(릴레이 터미널 A, 앱 터미널 B, CLI 기기 터미널 C). **기기 3대**를 만들려면 앱(`pc1`) + CLI 기기 `x`, `y`가 필요하다. `y`는 `x`와 같은 방법으로 `--profile y`, 이름 `cli-y`로 `init`·`join`한다(앱에서 `기기 추가`로 코드를 새로 받는다). 두 CLI 모두 `listen`을 켜 둔다.

1. **온라인 표시**: 앱의 기기 목록에서 `x`, `y`가 초록 점. `y`의 `listen`을 `Ctrl+C`로 끄면 잠시 뒤 `y`의 점이 회색으로 바뀌고, 다시 켜면 초록이 된다. 이 기기(앱) 점은 초록.
2. **이름 변경**: 앱의 `이 기기` 줄에서 `이름 변경` → `desk-1` → `저장`. 목록 이름이 바뀌고, 터미널 C에서 `cargo run -q -p clip-ferry-cli -- --profile x devices`에 `desk-1`이 보인다. 앱을 껐다 켜도 유지된다.
3. **제거**: `y` 줄의 `제거` → `취소`를 누르면 아무 일 없다. 다시 `제거` → `제거`. 목록에서 `y`가 사라지고 에포크가 올라간다. `y`에서 `cargo run -q -p clip-ferry-cli -- --profile y status`를 보면 제거 상태(다시 페어링하라는 안내)다. 이어서 앱에서 텍스트를 복사하면 `x`의 `listen`에는 나오지만 `y`에는 나오지 않는다.
4. **일시정지**: 앱 창의 `일시정지`(또는 트레이 아이콘 우클릭 → `일시정지`). 트레이가 회색이 되고 창 맨 위 상태 글자가 "일시정지". 앱에서 텍스트를 복사해도 `x`에 안 가고, `x`에서 `send hello`를 해도 앱 클립보드가 안 바뀐다. `재개`(창 버튼 또는 트레이 메뉴) 뒤 새로 복사한 텍스트는 `x`에 간다. 일시정지 중에 복사한 것은 재개해도 가지 않는다.
5. **보내기/받기 따로**: `보내기`만 끄면 앱 복사는 안 가고 `x`가 보낸 것은 클립보드에 써진다. `받기`만 끄면 반대. 앱을 껐다 켜도 설정이 유지된다.
6. **자동 시작**: `로그인할 때 자동으로 시작`을 켜고 **재부팅(또는 로그아웃/로그인)** 한 뒤 트레이에 앱이 떠 있는지 본다. 확인이 끝나면 다시 끈다. Windows는 `작업 관리자 → 시작 앱`에서도 보인다. (개발 모드 경로가 등록되므로 이 시험은 설치된 빌드가 있으면 그쪽으로 하는 편이 정확하다. macOS는 Mac이 없어 미확인.)
7. **다시 페어링**: 3번에서 제거한 기기가 앱이라면(앱을 `y` 자리에 두고 시험하려면 앱 프로필을 하나 더 띄우거나, CLI `x`로 앱을 제거한다: `cargo run -q -p clip-ferry-cli -- --profile x remove <앱 기기 이름>`) 앱이 곧 **"다시 페어링 필요"** 화면으로 바뀌고 트레이가 빨강이 된다. `다시 페어링` → `이 기기에서 그룹 정보 지우기` → 마법사가 뜨고 이름 칸은 그대로 잠겨 있다. `코드로 참여`로 `x`가 만든 초대 코드를 넣어 다시 참여하면 목록이 정상으로 돌아온다.
8. **회귀**: 일시정지가 아닐 때 텍스트·이미지 양방향 동기화가 이전과 같다.

## 정리

```powershell
Remove-Item -Recurse -Force .cf-profiles\x, .cf-profiles\y -ErrorAction SilentlyContinue
```
앱 프로필(`pc1`)은 `%APPDATA%\app.clipferry.desktop\profiles\pc1`을 지우면 처음부터 다시 시작한다. 자동 시작을 켰다면 꺼 두었는지 확인한다.

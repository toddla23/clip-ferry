# F43. 앱 기본 서버 주소 · 주소 숨기기 — 확인할 것

상태: `확인대기` (docs/05-progress.md). 브랜치 `f43-default-server` (F40 완료 커밋 위).

이 문서만 보고 처음부터 끝까지 따라 할 수 있게 썼다. 각 단계는 **할 일 → 보여야 하는 것** 순서다. 다르게 보이면 맨 아래 "막히면"을 먼저 보고, 그래도 안 되면 그 화면·문구를 "시험 중 나온 것"에 적는다.

## 무엇을 시험하나

- **배포 빌드**(Releases에 올라가는 exe·apk)는 주소를 넣지 않아도 공개 서버(`clipferry.japaneast.cloudapp.azure.com`)에 붙는다.
- 릴레이 주소는 계정 서버가 알려 준다(`GET /v1/config`). 앱은 켤 때·로그인할 때 받아서 그 주소로 연결한다.
- 화면에 서버 주소가 보이지 않는다. **제목을 3초 안에 7번 누르면** 서버 설정이 나타난다.
- 디버그 빌드(`npm run tauri dev`, `installDebug`)는 지금처럼 주소 칸이 보이고 기본값이 개발 서버다. 이번 시험은 배포 빌드로 한다.

아래에서 "VM에서"는 `ssh -i "$env:USERPROFILE\.ssh\clipferry_azure" jonghyeok@clipferry.japaneast.cloudapp.azure.com`으로 들어간 창이다.

## 1. 서버: 새 계정 서버 이미지로 바꾸기

Claude가 브랜치를 푸시하면 GitHub Actions의 **Images**가 `f43-default-server` 태그 이미지를 만든다(10~20분).

- [x] https://github.com/toddla23/clip-ferry/actions → **Images** → 브랜치 `f43-default-server` 실행의 두 작업이 초록

**VM에서**:
```bash
cd ~/clip-ferry && git fetch && git checkout f43-default-server && git pull
sed -i 's/^CF_IMAGE_TAG=.*/CF_IMAGE_TAG=f43-default-server/' deploy/.env.cloud
C="docker compose --env-file deploy/.env.cloud -f deploy/compose.cloud.yml"
$C pull && $C up -d && sleep 10 && $C ps
```
- [x] 4개 모두 `Up`

PC(PowerShell):
```powershell
curl.exe https://clipferry.japaneast.cloudapp.azure.com:8443/v1/config
```
- [x] `{"relay_url":"wss://clipferry.japaneast.cloudapp.azure.com"}`

## 3. PC (데스크톱 배포 빌드)

1. 트레이의 clip-ferry → **종료**
2. 받은 `…_x64-setup.exe` 실행 → SmartScreen이면 **추가 정보 → 실행** → 설치
3. 앱이 뜨면:
   - [-] 로그인 상태·그룹이 그대로이고 `연결됨` — 이번엔 앱 데이터가 지워져 해당 없음("시험 중 나온 것"), 새로 로그인해 확인
   - [x] 창 아래쪽에 **릴레이 주소 칸이 없다**
4. 처음 설치한 것처럼 해 보기: 트레이 → **종료** → PowerShell에서
   ```powershell
   Rename-Item "$env:APPDATA\app.clipferry.desktop\settings.json" settings.json.bak
   ```
   → 시작 메뉴에서 clip-ferry 실행
   - [x] 주소를 넣지 않았는데 `연결됨` (기본 주소 → 계정 서버가 알려 준 릴레이)
   - [x] 폰과 텍스트가 오간다
5. 로그아웃해 보기: 계정 칸 **로그아웃**
   - [x] 로그인 화면에 **`서버 설정` 버튼이 없다**
   - [x] 제목 `clip-ferry 로그인`을 빠르게 7번 누르면 `서버 설정`이 생기고, 열면 계정 서버 주소가 보인다
   - **Google로 로그인** → `연결됨`
6. 숨은 릴레이 칸 시험 (5에서 서버 설정을 켰으므로 이제 보인다):
   - 릴레이 주소 칸에 `wss://example.invalid` → 저장
     - [x] `재연결 중`에서 연결되지 않는다
   - 칸을 **비우고** 저장
     - [x] 곧 `연결됨`으로 돌아온다 (계정 서버가 알려 주는 주소로 돌아감)
7. 정리: 트레이 → 종료 →
   ```powershell
   Remove-Item "$env:APPDATA\app.clipferry.desktop\settings.json.bak"
   ```
   (4에서 새로 만든 settings.json을 그대로 쓴다. 서버 설정 칸을 다시 숨기려면 `settings.json`에서 `"show_server": true`를 `false`로)

## 4. 폰 (Android 배포 빌드)

1. 받은 `clip-ferry-…-android.apk`를 폰으로 옮겨 설치(업데이트) — PC에서 `adb install -r <파일>` 또는 파일을 폰에 복사해 누른다
   - [x] 덮어 설치된다 (`서명이 다르다`가 나오면 "막히면")
2. 앱을 연다
   - [x] 로그인·그룹이 그대로, `연결됨`
   - [x] 메인 화면에 **릴레이 주소 카드가 없고**, 계정 카드에 `계정 서버:` 줄이 없다
   - [x] 맨 위 `clip-ferry`를 빠르게 7번 누르면 릴레이 주소 카드가 나타난다
3. 동기화
   - [x] PC → 폰 텍스트, 폰 타일 → PC 텍스트

## 막히면

| 보이는 것 | 원인 | 할 일 |
|---|---|---|
| 1절 `curl`이 `404` | 계정 서버가 예전 이미지 | `CF_IMAGE_TAG`, Images 실행이 끝났는지 확인 후 `$C pull && $C up -d` |
| 1절 `{"relay_url":null}` | VM의 `compose.cloud.yml`이 예전 것 | VM에서 `git checkout f43-default-server && git pull` 했는지 → `$C up -d` |
| 3절 4번에서 `연결 끊김`·로그인 화면 | 로그인 정보는 남고 설정 파일만 지웠으니 연결돼야 한다 | `settings.json.bak`을 다시 `settings.json`으로 돌리고 화면 문구를 Claude에게 |
| 4절 `서명이 다르다`/`패키지가 기존 패키지와 충돌` | 폰 앱이 디버그 키로 깔려 있음 | 폰 앱을 지우고 설치(다시 로그인 → 계정 연결로 그룹 참여) |
| 제목을 7번 눌러도 안 나온다 | 3초 안에 7번이 안 됨 | 더 빠르게 |

## 시험 중 나온 것

- 2026-11-10 PC: 배포 빌드 설치 뒤 실행하자마자 꺼짐. `%APPDATA%\app.clipferry.desktop`이 비어 있고(`state.bin`·`settings.json` 없음) 자격 증명 관리자에는 키가 남아 코어가 "로컬 상태와 비밀 저장소가 서로 맞지 않습니다"로 열기를 거부 → setup 훅 panic(종료 코드 101). 데이터가 지워진 원인은 확인 중(설치 프로그램의 이전 버전 제거 때 앱 데이터 삭제로 추정). 할 일(F44로 넘김): 창 없이 꺼지지 말고 오류와 `처음부터 다시 시작`을 보여 준다. 사용자 조치: 남은 키 `cmdkey /delete` 후 새 기기로 로그인

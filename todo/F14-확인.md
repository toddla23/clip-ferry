# F14. 릴레이 배포 (1단계: 라즈베리파이 + Tailscale) — 해야 할 것과 확인할 것

상태: `완료` (docs/05-progress.md). 브랜치 `f14-relay-deploy`.

**확인 결과 (2026-11-02, 사용자 보고)**: 아래 1~4번 모두 통과. Pi 5(arm64)에서 빌드·기동, PC에서 Tailscale 너머 접속, 앱 ↔ CLI 텍스트·이미지 동기화 정상. `listen`에 자기 자신이 보낸 글이 안 나오는 것은 정상(같은 기기).

## 먼저 알아둘 것

- **범위가 줄었다.** 클라우드 배포 대신 집 Pi 5에 먼저 올려 시험한다(D-014). 클라우드·인증서·프록시 IP 처리는 이후 단계다.
- 릴레이는 Docker로 Pi(arm64)에 올리고, **Tailscale IP에만** 포트를 연다. 접속 주소는 `ws://<Pi의 Tailscale IP>:8787` (Pi는 `100.84.191.27`).
- `ws://`(평문)지만 Tailscale 구간은 WireGuard로 암호화되고, 클립보드 내용은 종단간 암호화다.
- `wss://`는 **서버 인증서가 있어야** 한다. 클라이언트(앱·CLI)는 이미 `wss://`를 지원하지만 실제 TLS 서버와는 아직 접속해 보지 않았다.
- 로컬 검증은 통과했다: fmt, clippy, `cargo test --workspace`, Docker 이미지 빌드(PC x86_64, 42 MB), 읽기 전용 루트 + `cap-drop ALL`로 컨테이너 기동과 `/healthz` 응답. **Pi(arm64) 빌드는 Pi에서 처음 확인한다.**

## 1. Pi에 올리기 (사용자)

```bash
git clone https://github.com/toddla23/clip-ferry.git
cd clip-ferry
git checkout f14-relay-deploy
echo "CF_BIND=$(tailscale ip -4)" > deploy/.env
docker compose -f deploy/compose.yml up -d --build
```

- [x] 빌드가 끝까지 성공한다(Pi 5에서 몇 분). 실패하면 출력을 그대로 알려 준다.
- [x] `docker compose -f deploy/compose.yml ps`에 relay가 `running`
- [x] Pi에서 `curl http://$(tailscale ip -4):8787/healthz` → `ok`
- [x] 로그에 `listening on 0.0.0.0:8787`: `docker compose -f deploy/compose.yml logs --tail 5`

## 2. PC에서 Pi 릴레이로 접속 (사용자)

- [x] PowerShell: `curl.exe http://100.84.191.27:8787/healthz` → `ok`
- [x] 같은 Wi-Fi가 아닌 곳(폰 핫스팟 등)에서도 되는지 — 서로 다른 네트워크 확인 (PC가 핫스팟에 붙은 상태에서 같은 `curl.exe`)
- [x] Pi를 LAN의 다른 IP로 접속하면 **안 열려야** 한다(Tailscale IP에만 바인드): `curl http://<Pi의 집 LAN IP>:8787/healthz` → 연결 거부

## 3. 앱·CLI로 동기화 시험 (사용자)

PC에서 릴레이를 따로 띄우지 않는다(Pi 릴레이만 쓴다). 터미널은 앱용(B), CLI용(C) 두 개를 쓴다. **모든 명령은 PowerShell**이고, 앱·CLI 모두 릴레이 주소는 `ws://100.84.191.27:8787`이다. 이전 시험의 프로필을 이미 지웠다면 아래 2번부터 새로 만든다.

### 3-1. 앱을 Pi 릴레이로 실행 (터미널 B)

```powershell
cd C:\Users\jonghyeok\Documents\clip-ferry
$env:CF_RELAY = "ws://100.84.191.27:8787"
cd apps\desktop
npm run tauri dev
```

- [x] 반드시 `apps\desktop`에서 `npm run tauri dev`를 실행한다(레포 루트에는 `package.json`이 없다)
- [x] 창에 `연결됨`이 뜬다. 안 뜨면 창의 릴레이 주소 설정에 같은 주소를 입력해 저장한다
- [x] 처음 실행이면 마법사에서 기기 이름(`pc1`) 입력 → `새 그룹`

### 3-2. CLI 기기 `x` 만들어 앱과 페어링 (터미널 C)

```powershell
cd C:\Users\jonghyeok\Documents\clip-ferry
cargo run -q -p clip-ferry-cli -- --profile x init --name cli-x
```

앱에서 `기기 추가`를 눌러 표시된 텍스트 코드를 복사한 뒤:

```powershell
cargo run -q -p clip-ferry-cli -- --profile x --relay ws://100.84.191.27:8787 join <코드>
```

- [x] 앱과 CLI에 **같은 6자리 숫자**가 뜬다 → 앱에서 승인
- [x] 앱 기기 목록에 `cli-x`가 나타난다(초록 점)
- [x] 코드가 10분 지났거나 한 번 썼다면 `기기 추가`로 새 코드를 받는다

### 3-3. 텍스트 양방향

수신을 켜 둔다(터미널 C, 켜 둔 채 둔다):

```powershell
cargo run -q -p clip-ferry-cli -- --profile x --relay ws://100.84.191.27:8787 listen
```

- [x] 앱 쪽에서 아무 텍스트(메모장에서 복사) → `listen`에 `[pc1] …`가 출력된다
- [x] 터미널 D(새 PowerShell)에서 보낸다:

  ```powershell
  cd C:\Users\jonghyeok\Documents\clip-ferry
  cargo run -q -p clip-ferry-cli -- --profile x --relay ws://100.84.191.27:8787 send "pi 릴레이에서 왔음"
  ```

  앱 클립보드에 써지므로 메모장에 `Ctrl+V`로 붙여넣어 확인한다. **`listen`(터미널 C)에는 아무것도 나오지 않는 게 정상이다.** `send`와 `listen`이 같은 프로필 `x`라서 자기가 보낸 메시지는 버려진다(03-protocol 2.2의 8번). `listen`에 나오는지는 위의 "앱 → CLI" 방향으로 본다
- [x] 한글이 깨져 보이면 `[Console]::OutputEncoding = [Text.Encoding]::UTF8`을 먼저 실행한다

### 3-4. 이미지

- [x] `Win+Shift+S`로 스크린샷을 찍으면 `listen`을 켠 폴더의 `.\received\`에 PNG가 저장된다
- [x] 5 MB 안팎의 큰 스크린샷도 도착한다(전체 화면 캡처)
- [x] CLI에서 앱으로: `cargo run -q -p clip-ferry-cli -- --profile x --relay ws://100.84.191.27:8787 send-image .\아무이미지.png` 뒤 그림판에 `Ctrl+V`

### 3-5. Pi 로그에 내용이 없는지 (Pi에서)

```bash
cd ~/clip-ferry
docker compose -f deploy/compose.yml logs --tail 20
```

- [x] 연결 수·프레임·바이트 집계만 있고, 텍스트나 채널 ID·기기 태그가 없다

### 3-6. 재연결 (Pi에서 릴레이를 껐다 켠다)

```bash

```

- [x] 앱 창이 잠시 `재연결 중` → `연결됨`, CLI `listen`도 `reconnecting` → `connected`
- [x] 재연결 뒤 앱에서 새로 복사한 텍스트가 `listen`에 다시 도착한다

## 정리 (시험 후)

PC (PowerShell):

```powershell
cd C:\Users\jonghyeok\Documents\clip-ferry
Remove-Item -Recurse -Force .cf-profiles, received -ErrorAction SilentlyContinue
Remove-Item Env:CF_RELAY -ErrorAction SilentlyContinue
```

- 앱 프로필을 지우려면 `%APPDATA%\app.clipferry.desktop`을 지운다. 이때 **Windows 자격 증명 관리자의 `clip-ferry` 항목도 같이 지워야** 한다(한쪽만 지우면 "로컬 상태와 비밀 저장소가 서로 맞지 않습니다"로 앱이 안 뜬다).
- 앱 설정에 Pi 주소가 저장됐다면 이후 로컬 릴레이로 돌아갈 때 창에서 `ws://127.0.0.1:8787`로 되돌린다.

Pi는 계속 켜 둘 거면 그대로 둔다. 멈추려면 `docker compose -f deploy/compose.yml down`.

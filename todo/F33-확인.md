# F33. 릴레이 접속 토큰 확인 · 계정별 제한 · 사용량 — 확인할 것

상태: `확인대기` (docs/05-progress.md). 브랜치 `f33-relay-auth`.

## 먼저 알아둘 것

- 이번 범위: 릴레이가 **계정 서버가 발급한 접속 토큰이 있는 연결만** 받게 하는 기능과, 계정별 제한·사용량. 앱(데스크톱·Android) 로그인 화면은 F34·F35다. 그래서 이번 시험은 **PC에서 CLI로** 한다.
- 켜고 끄기: 릴레이에 계정 서버 주소(`--account-url`)를 줄 때만 토큰을 확인한다. 주지 않으면 지금처럼 누구나 접속된다. **Pi 릴레이에서는 아직 켜지 않는다**(켜면 지금 쓰는 PC·폰 앱 동기화가 끊긴다. F34·F35 뒤에 `deploy/compose.relay-auth.yml`로 켠다).
- 확인하는 것: 토큰 없음·가짜·만료 → 거부(HTTP 401), 계정당 동시 연결 수(429)·분당 바이트(`RATE_LIMITED`) 따로, 계정별 게시 수·바이트를 1분마다 계정 서버에 보냄(내용 없음). 릴레이 로그에는 숫자만.
- 이미 해 둔 것(Windows): 릴레이 인증 통합 테스트 7개(실제 계정 서버 + 릴레이 + 코어), 계정 서버 사용량 API 테스트(메모리·MariaDB), 기존 테스트 전부 통과. 실제 실행 파일로 아래 1~4를 한 번 돌려 봤다(미로그인 거부, 로그인 후 연결, 1분 뒤 사용량 `messages 2`).
- 한 번, 전체 재컴파일 직후에 테스트가 하나 실패하고 이후 10번은 통과했다(어느 테스트인지 출력이 잘려 모름. 시간에 민감한 테스트로 추정). CI에서 지켜본다.

## 준비 (PowerShell 창 3개, 모두 저장소 폴더에서)

**창 1 — 계정 서버** (메모리, 개발용 로그인, 사용량 비밀 `test123`)
```powershell
$env:CF_ACCOUNT_SIGNING_KEY = (cargo run -q -p clip-ferry-account -- gen-key)
cargo run -q -p clip-ferry-account -- --memory-store --dev-login --usage-secret test123
```
- [x] `listening on 127.0.0.1:8788`

**창 2 — 릴레이** (토큰 확인 켬)
```powershell
cargo run -q -p clip-ferry-relay -- --account-url http://127.0.0.1:8788 --usage-secret test123
```
- [x] `access tokens required (account server set)` 와 `listening on 127.0.0.1:8787`

**창 3 — CLI** (아래 `cf`는 매번 `cargo run -q -p clip-ferry-cli --`로 바꿔 친다. 시험용 프로필 폴더를 따로 쓴다)
```powershell
$env:CF_PROFILES_DIR = "$env:TEMP\cf-f33"
function cf { cargo run -q -p clip-ferry-cli -- @args }
cf --profile a init --name pc-a
cf --profile a group create
```

## 1. 로그인 안 하면 거부

```powershell
cf --profile a status
cf --profile a send "hello"
```
- [x] `status`의 `릴레이: disconnected`
- [x] `send`가 `릴레이가 접속 토큰을 받지 않았습니다 (cf login --dev로 로그인)`를 (몇 번) 찍고 5초 뒤 `릴레이(…)에 연결할 수 없습니다`로 끝난다

## 2. 로그인하면 연결

```powershell
cf --profile a login --dev --email me@test.dev --name 시험
cf --profile a status
cf --profile a account
```
- [x] `로그인됨: me@test.dev`
- [x] `status`의 `릴레이: connected`
- [x] `account`에 내 이메일, `usage: []`

## 3. 두 기기로 주고받기

```powershell
cf --profile b init --name pc-b
cf --profile b login --dev --email me@test.dev
cf --profile a invite          # 코드가 뜬다. 이 창은 그대로 두고
```
새 PowerShell 창(창 4)에서 (같은 `$env:CF_PROFILES_DIR`와 `function cf`를 먼저 다시 친다):
```powershell
cf --profile b join <코드>
```
- [x] 양쪽 같은 숫자 → 창 3에서 `y` → `joined`
- [x] 창 4: `cf --profile b listen` / 창 3: `cf --profile a send "안녕 F33"` → 창 4에 `[pc-a] 안녕 F33`

## 4. 사용량이 계정 서버에 쌓인다

1분쯤 기다린 뒤:
```powershell
cf --profile a account
```
- [x] `usage`에 오늘 날짜 한 줄, `messages`가 보낸 수(+ 연결할 때마다 1건씩 그룹 확인 메시지), `bytes`가 0보다 크다
- [x] 창 2(릴레이) 로그에 1분마다 `connections=… unauthorized=…` 숫자 줄만 있고 이메일·토큰·계정 ID가 없다

## 5. 로그아웃

```powershell
cf --profile a logout
cf --profile a status
```
- [x] `로그아웃됨`, 그 뒤 `릴레이: disconnected`

## 6. 토큰 확인을 끈 릴레이는 그대로 (회귀)

창 2를 Ctrl+C로 끄고 `--account-url` 없이 다시 띄운다:
```powershell
cargo run -q -p clip-ferry-relay
```
- [x] 로그에 `no account server: accepting connections without access tokens`
- [x] `cf --profile a status`(로그아웃 상태) → `릴레이: connected`
- [x] (선택) PC 데스크톱 앱을 이 브랜치로 `npm run tauri dev` 하면 지금처럼 동기화된다

## 알려진 사항

- 토큰은 **연결할 때만** 확인한다. 연결 중 토큰이 만료되거나 계정을 지워도(F39) 그 연결은 끊길 때까지 유지된다(최대 1시간 뒤 재연결 때 막힘).
- CLI 로그인은 개발 전용이다(D-010). 토큰을 프로필 폴더 `account.json`에 평문으로 둔다. 앱은 F34~F36에서 보안 저장소에 둔다.
- Pi 릴레이에서 켜는 것은 F34·F35 뒤 (`deploy/README.md` "릴레이가 접속 토큰을 확인하게 하기").

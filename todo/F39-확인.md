# F39. 계정 삭제(서버) · 개인정보처리방침 — 확인할 것

상태: `완료` (docs/05-progress.md). 브랜치 `f39-account-delete` (F38 완료 커밋 위).

이 문서만 보고 처음부터 끝까지 따라 할 수 있게 썼다. 각 단계는 **할 일 → 보여야 하는 것** 순서다. 다르게 보이면 맨 아래 "막히면"을 먼저 보고, 그래도 안 되면 그 화면·문구를 "시험 중 나온 것"에 적는다.

## 무엇을 시험하나

- 계정 서버의 `DELETE /v1/me`가 그 계정의 계정 정보·기기 목록·로그인 토큰·사용량을 바로 지운다.
  - 지운 뒤에는 그 계정의 토큰으로 계정 API를 못 쓰고, 로그인 유지(갱신)도 안 된다.
  - 운영자 페이지에서도 사라진다.
- 일별 사용량은 13개월 뒤 자동으로 지운다(자동 테스트 `prune_drops_usage_older_than_retention`로 확인).
- `docs/privacy.md` 초안을 읽어 본다.
- **앱은 바뀌지 않았다**(2026-11-09 사용자 결정, D-024). 앱에는 계정 삭제 버튼이 없고, 삭제는 나중에 만들 홈페이지(F40)에서 한다. 그래서 PC 앱·폰은 시험하지 않는다.
- **진짜 계정은 지우지 않는다.** 개발용 시험 계정을 만들어 지운다.

## 1. Pi: 계정 서버를 이 브랜치로 다시 빌드 + 개발용 로그인 켜기

**Pi에서** (SSH):
```bash
cd ~/clip-ferry && git fetch && git checkout f39-account-delete && git pull
grep -q '^CF_DEV_LOGIN=' deploy/.env.account && sed -i 's/^CF_DEV_LOGIN=.*/CF_DEV_LOGIN=true/' deploy/.env.account || echo "CF_DEV_LOGIN=true" >> deploy/.env.account
grep CF_DEV_LOGIN deploy/.env.account
docker compose --env-file deploy/.env.account -f deploy/compose.account.yml up -d --build
```
- [x] `grep` 결과가 `CF_DEV_LOGIN=true`
- 다시 빌드는 10~20분. **릴레이(`compose.yml`)는 다시 올리지 않는다.**

다 되면 (Pi에서):
```bash
docker compose --env-file deploy/.env.account -f deploy/compose.account.yml logs account | tail -5
curl -s -o /dev/null -w "%{http_code}\n" -X DELETE https://raspberry-pi.tailb6b7a3.ts.net:8443/v1/me
```
- [x] 로그에 `dev login enabled: …` 경고 줄
- [x] `curl`이 `401` (새 경로가 있고, 로그인 없이는 지울 수 없다). `405`면 예전 코드 → 위를 다시

## 2. 시험 계정을 만들고 지운다 (Pi에서)

아래를 **한 번에** 붙여 넣는다. 시험 계정 `f39@test.dev`로 로그인해 기기를 하나 등록한다.
```bash
U=https://raspberry-pi.tailb6b7a3.ts.net:8443
LOGIN=$(curl -s -X POST -H "Content-Type: application/json" -d '{"email":"f39@test.dev"}' $U/v1/auth/dev)
TOK=$(echo "$LOGIN" | sed -n 's/.*"access_token":"\([^"]*\)".*/\1/p')
REF=$(echo "$LOGIN" | sed -n 's/.*"refresh_token":"\([^"]*\)".*/\1/p')
echo "login: $([ -n "$TOK" ] && echo ok || echo FAIL)"
curl -s -o /dev/null -w "device: %{http_code}\n" -X PUT -H "Authorization: Bearer $TOK" -H "Content-Type: application/json" -d '{"name":"시험 PC","platform":"windows"}' $U/v1/devices/0123456789abcdef0123456789abcdef
curl -s -o /dev/null -w "me before: %{http_code}\n" -H "Authorization: Bearer $TOK" $U/v1/me
```
- [x] `login: ok`, `device: 200`, `me before: 200`

1. (운영자 페이지) PC 브라우저로 `https://raspberry-pi.tailb6b7a3.ts.net:8443/admin` → `사용자` 검색에 `f39`
   - [ ] `f39@test.dev` 한 줄, 로그인 `dev`, 기기 1

이어서 (Pi에서, **같은 창**):
```bash
curl -s -o /dev/null -w "delete: %{http_code}\n" -X DELETE -H "Authorization: Bearer $TOK" $U/v1/me
curl -s -o /dev/null -w "delete again: %{http_code}\n" -X DELETE -H "Authorization: Bearer $TOK" $U/v1/me
curl -s -o /dev/null -w "me after: %{http_code}\n" -H "Authorization: Bearer $TOK" $U/v1/me
curl -s -o /dev/null -w "device after: %{http_code}\n" -X PUT -H "Authorization: Bearer $TOK" -H "Content-Type: application/json" -d '{"name":"시험 PC","platform":"windows"}' $U/v1/devices/0123456789abcdef0123456789abcdef
curl -s -o /dev/null -w "refresh after: %{http_code}\n" -X POST -H "Content-Type: application/json" -d "{\"refresh_token\":\"$REF\"}" $U/v1/auth/refresh
docker compose --env-file deploy/.env.account -f deploy/compose.account.yml logs account | tail -3
```
- [x] `delete: 204`, `delete again: 204` (두 번 지워도 된다)
- [x] `me after: 401`, `device after: 401` (지운 계정의 토큰으로는 계정 API를 못 쓴다)
- [x] `refresh after: 401` (로그인 유지가 풀린다 → 앱이라면 로그인 화면으로 간다)
- [x] 로그 끝에 `account deleted` (이메일은 로그에 남지 않는다)

2. (운영자 페이지) 새로 고침 → `f39` 검색
   - [ ] `찾는 사용자가 없습니다`

## 시험 중 나온 것

1. (앱 시험 때, 지금은 없어진 절) 앱 B를 앱 A보다 먼저 켜 둬서 `npm run tauri dev`가 `clip-ferry-desktop.exe … 액세스가 거부되었습니다`로 실패. 그 앱 B에서 실수로 `새 그룹 만들기`, 이어서 프로필 `f39a`의 상태 파일만 없어져 `로컬 상태와 비밀 저장소가 서로 맞지 않습니다`로 켜지지 않음 → f39 시험 프로필·자격 증명을 모두 지우고, 서버의 시험 계정도 `DELETE /v1/me`로 지움(204 → 401 확인)
2. (범위 변경, 사용자 결정) 앱의 `계정 삭제` 버튼·경로를 빼고 삭제는 홈페이지(F40)에서 하기로 함 → 데스크톱·FFI·Android 변경을 되돌리고 이 문서를 서버 확인만으로 다시 씀
3. 2절 로그 확인·정리 명령을 홈 폴더(`~`)에서 실행해 `couldn't find env file` → `cd ~/clip-ferry` 뒤 다시 실행해 통과(`account deleted` 2줄 — 앞서 지운 시험 계정 포함)
4. 정리 때 `docker compose … up -d`가 `a network with name clip-ferry-account exists but was not created for project "clip-ferry-account"` 경고. 컨테이너는 정상 기동(MariaDB Healthy, account Started). 동작에는 영향 없음

## 알려진 사항

- 삭제한 계정의 **이미 받은 접속 토큰**은 만료(최대 1시간)까지 릴레이 접속에 쓰일 수 있다. 릴레이는 DB를 보지 않기 때문이다. 그 계정의 기기는 다음 토큰 갱신 때(최대 1시간) 로그아웃된다(D-024).
- 기기의 그룹 정보(그룹 키)는 서버에 없으므로 서버 삭제와 상관없이 각 기기에 남는다.
- 같은 구글 계정으로 다시 로그인하면 새 계정(새 계정 ID)으로 시작한다.
- **스토어**: App Store는 앱 안에서 삭제를 시작할 수 있어야 하고, Google Play는 앱 안 경로와 웹 링크를 둘 다 요구한다. 지금 앱에는 경로가 없으므로 스토어에 내기 전에 다시 정한다(D-024, F40).

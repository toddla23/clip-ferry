# F39. 계정 삭제 · 개인정보처리방침 — 확인할 것

상태: `진행중` (docs/05-progress.md). 브랜치 `f39-account-delete` (F38 완료 커밋 위).

이 문서만 보고 처음부터 끝까지 따라 할 수 있게 썼다. 각 단계는 **할 일 → 보여야 하는 것** 순서다. 다르게 보이면 맨 아래 "막히면"을 먼저 보고, 그래도 안 되면 그 화면·문구를 "시험 중 나온 것"에 적는다.

## 무엇을 시험하나

- 앱의 `계정 삭제`를 누르면:
  - 서버에서 그 계정의 계정 정보, 기기 목록, 사용량, 로그인 토큰이 바로 지워진다.
  - 이 기기의 로그인과 그룹 정보가 지워지고 로그인 화면으로 간다.
  - 같은 계정으로 로그인한 다른 기기는 다음 토큰 갱신 때 로그아웃된다.
- 삭제가 실패하면(서버에 못 닿음) 아무것도 바뀌지 않는다.
- 일별 사용량은 13개월 뒤 자동으로 지운다(자동 테스트로 확인).
- `docs/privacy.md` 초안을 읽어 본다.

**진짜 계정(폰·설치된 PC 앱이 쓰는 구글 계정)은 지우지 않는다.** 실제 삭제는 개발용 시험 계정으로 데스크톱에서만 한다. 폰에서는 확인 창, 취소, 실패 경로만 본다.

## 시험 구성

```
Pi   계정 서버(이 브랜치) — 시험하는 동안만 개발용 로그인(CF_DEV_LOGIN) 켬
PC   앱 A  프로필 f39a  (npm run tauri dev)           — 개발용 계정 f39@test.dev, 새 그룹
PC   앱 B  프로필 f39b  (앱 A가 빌드한 exe 직접 실행)   — 같은 개발용 계정, 계정 연결로 A의 그룹에 참여
폰   이 브랜치 앱(versionCode 7) — 진짜 계정 그대로, 삭제하지 않음
```

## 1. Pi: 계정 서버를 이 브랜치로 다시 빌드 + 개발용 로그인 켜기

**Pi에서** (SSH):
```bash
cd ~/clip-ferry && git fetch && git checkout f39-account-delete && git pull
grep -q '^CF_DEV_LOGIN=' deploy/.env.account && sed -i 's/^CF_DEV_LOGIN=.*/CF_DEV_LOGIN=true/' deploy/.env.account || echo "CF_DEV_LOGIN=true" >> deploy/.env.account
grep CF_DEV_LOGIN deploy/.env.account
docker compose --env-file deploy/.env.account -f deploy/compose.account.yml up -d --build
```
- [ ] `grep` 결과가 `CF_DEV_LOGIN=true`
- 다시 빌드는 10~20분. **릴레이(`compose.yml`)는 다시 올리지 않는다.**

다 되면 (Pi에서):
```bash
docker compose --env-file deploy/.env.account -f deploy/compose.account.yml logs account | tail -5
curl -s -o /dev/null -w "%{http_code}\n" -X DELETE https://raspberry-pi.tailb6b7a3.ts.net:8443/v1/me
```
- [ ] 로그에 `dev login enabled: …` 경고 줄
- [ ] `curl`이 `401` (새 경로가 있고, 로그인 없이는 지울 수 없다). `405`면 예전 코드 → 위를 다시

## 3. 폰: 확인 창과 실패 경로 (진짜 계정은 지우지 않는다)

### 3-1. 폰에 이 브랜치 앱 설치 (PowerShell, 폰은 무선 디버깅 또는 USB)

```powershell
cd C:\Users\jonghyeok\Documents\clip-ferry
.\scripts\build-android-core.ps1
$k = "$env:USERPROFILE\.clip-ferry-release"
$env:CLIPFERRY_KEYSTORE = "$k\release.jks"
$env:CLIPFERRY_KEYSTORE_PASSWORD = (Get-Content "$k\password.txt" -Raw).Trim()
$env:CLIPFERRY_VERSION_CODE = "7"
$env:CLIPFERRY_VERSION_NAME = "0.1.0-f39"
cd apps\android
.\gradlew.bat installRelease
```
- 무선 디버깅이면 먼저 `& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" connect 100.111.91.121:<무선 디버깅 화면의 포트>` (페어링은 이미 했다)
- **앱을 지우지 않는다**(지우면 폰의 그룹이 사라진다).
- [ ] 마지막이 `BUILD SUCCESSFUL`, 그 위에 `Installed on 1 device.`
- [ ] 폰 clip-ferry가 로그인된 채 `연결됨`

### 3-2. 확인 창과 취소

1. 메인 화면 아래쪽 `계정` 카드
   - [ ] 버튼 `로그아웃`·`계정 삭제`
2. `계정 삭제`
   - [ ] 대화상자 `계정을 삭제할까요?`, 설명(되돌릴 수 없음·다른 기기도 로그아웃·그룹 정보도 지움), 버튼 `취소`·`계정 삭제`(빨강)
3. **`취소`**
   - [ ] 대화상자가 닫히고 그대로 `연결됨`

### 3-3. 실패하면 아무것도 바뀌지 않는다

4. 폰을 **비행기 모드**로 하고 Wi-Fi도 꺼져 있는지 본다
   - [ ] 앱 위쪽이 `재연결 중`(또는 연결 안 됨). **`연결됨`이면 다음으로 넘어가지 않는다**(진짜 계정이 지워진다)
5. `계정 삭제` → 대화상자의 `계정 삭제`
   - [ ] 계정 카드에 빨간 글씨 `계정 서버(…)에 연결하지 못했습니다`
   - [ ] 계정 이메일과 기기 목록이 그대로다
6. 비행기 모드 끄기
   - [ ] 잠시 뒤 `연결됨`, 기기 목록 그대로. PC와 글 주고받기가 된다

## 알려진 사항

- 삭제한 계정의 **이미 받은 접속 토큰**은 만료(최대 1시간)까지 릴레이 접속에 쓰일 수 있다. 릴레이는 DB를 보지 않기 때문이다. 다른 기기는 다음 토큰 갱신 때(최대 1시간) 로그아웃된다(D-024).
- 삭제는 **이 기기의** 그룹 정보만 지운다. 같은 그룹의 다른 기기 목록에는 이 기기가 남으니 필요하면 거기서 `제거`한다.
- 같은 구글 계정으로 다시 로그인하면 새 계정(새 계정 ID)으로 시작한다.
- Google Play는 앱 밖에서도 삭제를 요청할 웹 링크를 요구한다 → F40에서 만든다(`docs/privacy.md` 작성 메모).
- iOS 앱의 계정 삭제는 F36(iOS 로그인)에서 같은 화면으로 넣는다.

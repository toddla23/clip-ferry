# F15. Android 셸 기본 + 코어 바인딩 — 확인할 것

상태: `완료` (docs/05-progress.md). 브랜치 `f15-android-shell`.

## 먼저 알아둘 것

- 이번 범위: Android 앱이 코어(Rust)에 연결되어 **상태를 표시하고 백그라운드에서 연결을 유지**하는 것. 페어링(F16)·클립보드(F17~)는 아직 없다.
- 페어링 화면이 없으므로 앱은 처음 실행 때 **혼자인 그룹을 임시로 자동 생성**한다(데스크톱 F09와 같은 방식). 그래서 릴레이에 붙으면 `연결됨`, 온라인 기기는 1대(이 기기)다.
- 빌드는 이미 확인했다(Windows): `cargo fmt/clippy`, 코어·FFI 단위 테스트, `.so`(arm64-v8a·x86_64) 빌드, Kotlin 바인딩 생성, `./gradlew assembleDebug` 성공(APK 약 20 MB). **실제로 실행해 본 적은 아직 없다.** 에뮬레이터는 PC 메모리(가용 7 GB)가 부족해 접었고, 실기기로 확인한다.
- 앱은 릴레이 주소를 **화면에서 직접 입력**한다. 기본값은 에뮬레이터용 개발 주소(`ws://10.0.2.2:8787`)라 폰에서는 반드시 바꿔야 한다. 정식 기본 주소는 O-03(도메인) 결정 뒤.
- 네이티브 소켓(Rust)은 안드로이드의 평문 차단 정책(Network Security Config)을 받지 않을 가능성이 높다. `ws://`로 접속되는지도 이번에 같이 본다(되더라도 모바일 정식 주소는 `wss://`).

## 0. 준비 (PC)

1. 환경 변수(이미 설정됨): `ANDROID_HOME`, `ANDROID_NDK_HOME`. 새 PowerShell을 연다.
2. 폰: 설정 → 개발자 옵션 → **USB 디버깅** 켜기 → USB로 PC에 연결 → 폰의 허용 팝업 승인.
3. 폰에 **Tailscale 앱** 설치·로그인(PC·Pi와 같은 tailnet). `wss://raspberry-pi.tailb6b7a3.ts.net`에 닿으려면 필요하다.
4. 확인: PowerShell에서

   ```powershell
   & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" devices
   ```

   → 기기가 `device`로 보인다(`unauthorized`면 폰 팝업 승인).

## 1. 빌드·설치 (PC, PowerShell)

```powershell
cd C:\Users\jonghyeok\Documents\clip-ferry
git checkout f15-android-shell
.\scripts\build-android-core.ps1
cd apps\android
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
.\gradlew.bat installDebug
```

- [x] `build-android-core.ps1`가 `완료`를 출력한다
- [x] `installDebug`가 `BUILD SUCCESSFUL` (처음에는 의존성을 받느라 10분 넘게 걸릴 수 있다)
- 또는 Android Studio에서 `apps/android`를 열어 ▶ 실행(동기화 전에 위의 `build-android-core.ps1`을 먼저 한 번 실행해야 한다)

## 2. 연결 확인

1. 앱을 연다 → 알림 권한 팝업에서 **허용**.
2. 화면의 `릴레이 주소`에 `wss://raspberry-pi.tailb6b7a3.ts.net` 입력 → `저장하고 다시 연결`.
   (Tailscale 앱이 켜져 있어야 한다.)

- [x] 상단에 `연결됨`, `이 기기: <폰 모델> (<8자리>)`, `에포크 1 · 구성원 1대`, `지금 연결된 기기 1대`
- [x] 상단 알림창에 상시 알림 `clip-ferry · 연결됨`
- [x] Pi 로그에서 접속이 늘고 줄어드는 것이 보인다: `docker compose -f deploy/compose.yml logs --tail 10` (내용·채널 ID 없이 집계만)
- [x] (선택) 평문 접속 시험: PC에서 `cargo run -p clip-ferry-relay -- --listen 0.0.0.0:8787`을 켜고, 앱 주소를 `ws://<PC의 LAN IP>:8787`로 바꿔 `연결됨`이 되는지. 안 되면 결과를 알려 달라(정책 결정에 쓴다)
  - 결과: `ws://<LAN IP>:8787`로 `연결됨`. 안드로이드 평문 차단이 코어(Rust) 소켓에는 적용되지 않는다

## 3. 백그라운드 유지

- [x] 최근 앱 화면에서 clip-ferry를 위로 밀어 지워도 상시 알림이 남는다
- [x] 앱을 다시 열면 바로 `연결됨`이다
- [x] 알림의 `중지`를 누르면 알림이 사라진다. 앱을 열면 `백그라운드 연결 유지`가 꺼져 있고 `연결 안 됨`이다. 스위치를 켜면 다시 연결된다
- [x] 화면 잠금을 5분 이상 둔 뒤에도 `연결됨` (배터리 최적화 영향 확인. 안 되면 아래 4번을 적용하고 다시)

## 4. 배터리 최적화 안내 화면

- [x] `배터리 최적화` 카드에 `배터리 최적화 설정 열기` 버튼이 있고 누르면 시스템 설정 목록이 열린다
- [x] 목록에서 clip-ferry를 `최적화 안 함`으로 바꾸고 앱으로 돌아오면 카드가 `제외되어 있습니다`로 바뀐다

## 5. 네트워크 전환

- [x] Wi-Fi를 끄고 LTE로 바뀔 때: 잠깐 `재연결 중` 후 `연결됨` (Tailscale이 켜져 있어야 릴레이에 닿는다)
- [x] 다시 Wi-Fi를 켜도 `연결됨`
- [x] 비행기 모드 켰다 끄기 → `재연결 중` → `연결됨`
- [x] Pi 릴레이를 껐다 켜면(`docker compose -f deploy/compose.yml restart`) `재연결 중` → `연결됨`

## 6. 재시작 후 같은 기기

- [x] 앱을 완전히 종료(설정 → 앱 → 강제 종료)하고 다시 열어도 같은 `이 기기: … (<8자리>)`이다 (Keystore에 저장된 키 확인)
- [x] 폰을 재부팅한 뒤에는 서비스가 자동으로 뜨지 **않는다**(부팅 시 자동 시작은 이번 범위 밖). 앱을 열면 다시 연결된다

## 알려진 사항 (이번 범위 밖)

- 페어링·기기 추가·클립보드 송수신 없음 (F16~F19)
- 폰이 재부팅되면 앱을 한 번 열어야 연결된다
- 회선이 모두 끊긴 뒤 `재연결 중` 표시까지 약 15초 걸린다(안드로이드 회선 소실 알림 지연). 허용하기로 함
- 배터리 최적화 목록은 기본 필터에 clip-ferry가 없다. "모든 앱"으로 바꿔야 보인다
- 데이터 백업은 일부러 막았다(Keystore 키는 기기 밖으로 못 나가므로 복원해도 열 수 없다)
- 임시 자동 그룹 생성은 F16에서 마법사(새 그룹 / 코드로 참여)로 바뀐다

## 정리

앱을 지우려면: `adb uninstall app.clipferry.android` (Keystore 키와 저장 데이터가 함께 지워진다)
